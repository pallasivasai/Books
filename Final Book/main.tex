\chapter{Unit 1 -- IT--ITeS and the Data Entry Workplace}
\section{From facts to useful information}
Data consists of recorded facts such as a name, date, quantity, identification number or attendance mark. Information is data arranged and interpreted so that it can answer a question. A list of daily attendance marks becomes more useful when it is organised by class and date and checked for missing entries. The computer stores and processes the entries, but a person still has to decide whether the information is complete and appropriate for its purpose.
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/it_ites_workflow.png}{\includegraphics[width=.82\textwidth]{../Domestic data entry operator-9th/book_illustrations/it_ites_workflow.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: it ites workflow}}\end{center}}\end{center}
\section{What a data-entry operator may do}
The work can include reading information from a form, entering it into a digital system, checking required fields, correcting errors against the source, updating an existing record, retrieving a record when authorised, and preparing a simple work report. The exact task depends on the organisation. In a school, a practice example might be an inventory list; in a clinic, records would be sensitive and require strict access controls. For classroom work, use fictional names and numbers.
\section{Five dimensions of record quality}
\begin{enumerate}
\item \textbf{Accuracy:} the entry matches the trusted source.
\item \textbf{Completeness:} required fields are present, or missing information is clearly flagged.
\item \textbf{Consistency:} the same kind of value is recorded in the same format.
\item \textbf{Timeliness:} the record is entered and updated when required.
\item \textbf{Traceability:} a reviewer can understand where the value came from and what was checked, without exposing information to unauthorised people.
\end{enumerate}
These qualities can conflict with pressure to work quickly. A fast entry is not good work if a digit is wrong or a required field is guessed. Teach learners to maintain a steady pace and build checks into the workflow.
\section{A practical example: registration records}
Give pairs a fictional registration sheet containing eight records. Include a few deliberate issues: one missing phone number, a date written in a different format, one transposed digit in an ID, and one record with extra spaces. Ask learners to enter the records into a table and mark the issues they can identify. They must not invent a value to fill a blank. The correct response to missing source information is to flag it for clarification according to the agreed process.
\section{The source of truth}
When two values disagree, learners should not choose whichever looks more plausible. They should return to the designated source or ask the authorised supervisor. This habit matters because a plausible guess can become a false record that is copied into later reports. Demonstrate a clear correction note or flag where the local process allows it.

\section{Lesson plan outline}
Begin with examples of records learners recognise, such as a library book list or school equipment register. Ask what could go wrong if the data were inaccurate. Demonstrate one record from source to checked entry. Let pairs complete a short set and then compare against the source. End by asking each learner to name one check they will perform before submitting work.



\chapter{Unit 2 -- Keyboarding, Accuracy and Workstation Practice}
\section{A comfortable workstation}
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/workstation_posture.png}{\includegraphics[width=.72\textwidth]{../Domestic data entry operator-9th/book_illustrations/workstation_posture.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: workstation posture}}\end{center}}\end{center}
Invite learners to adjust their chairs and screens so they can work without straining. Feet should be supported where possible, shoulders relaxed and wrists in a comfortable neutral position. The screen should be readable without leaning forward for long periods. There is no single posture that fits every body; the practical aim is to reduce unnecessary strain and allow regular changes of position.
\section{Keyboard groups and familiarisation}
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/keyboard_groups.png}{\includegraphics[width=.82\textwidth]{../Domestic data entry operator-9th/book_illustrations/keyboard_groups.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: keyboard groups}}\end{center}}\end{center}
Explain the letter keys, number row, numeric keypad where available, function keys, navigation keys and modifier keys such as Shift, Ctrl and Alt. The layout varies between keyboards, so learners should identify the controls on the equipment they actually use. Ask them to locate Backspace, Enter, Shift, Spacebar and the arrow keys before beginning a timed activity.
\section{Build a practice sequence}
A beginner benefits from short, focused practice. Start with familiar letter patterns, then common words, sentences, punctuation and numeric strings. Keep the source text visible and teach learners to compare the typed result with it. When a learner makes repeated errors, shorten the passage and return to the keys or combinations causing difficulty. Do not increase the time pressure just because the class is progressing at different speeds.
\subsection{Accuracy before speed}
Speed is meaningful only when measured alongside accuracy and under comparable conditions. If two attempts use different text lengths or difficulty, their results cannot be compared fairly. Use the same duration, similar text and the same method for each attempt. Give feedback on one or two observable behaviours: for example, “You checked each line before moving on,” or “Your number entries were accurate when you paused to compare the source.”
\subsection{Simple recording sheet}
\begin{center}\small\begin{tabularx}{\textwidth}{|X|c|c|X|}\hline
\textbf{Attempt} & \textbf{Duration} & \textbf{Errors found} & \textbf{Next practice goal}\\\hline
1 & 2 min & & \\\hline
2 & 2 min & & \\\hline
3 & 2 min & & \\\hline
\end{tabularx}\end{center}
\section{Common difficulties and coaching responses}
If a learner looks down at every key, reduce the task to a small set of keys and practise slowly. If the learner types quickly but misses characters, ask them to pause at the end of each line and compare. If they press the wrong modifier key, demonstrate the combination slowly and let them repeat it several times. If discomfort appears, stop and adjust the setup rather than asking the learner to push through it.

\section{Feedback that motivates}
Use evidence instead of labels. “You made six errors” is information, but it is not a plan. A more useful comment is: “Four errors were in the number sequence. For the next attempt, read each group of three digits, enter it, and compare it before continuing.” Make the next step small enough to be achievable.



\chapter{Unit 3 -- Digital Documentation}
\section{A document is more than typed words}
A useful document has a clear purpose, readable structure and a reliable saved copy. Learners should be able to create a new file, enter text, correct mistakes, format headings, save in the correct folder, close the document and reopen it. The precise menu names differ across word processors, but the sequence remains useful across applications.
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/document_workflow.png}{\includegraphics[width=.8\textwidth]{../Domestic data entry operator-9th/book_illustrations/document_workflow.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: document workflow}}\end{center}}\end{center}
\section{Demonstration: prepare a school notice}
Use a fictional school event. Include a heading, date, venue, a short explanation, instructions and a contact role rather than a real phone number. First discuss what the reader needs to know. Type the content, check spelling and punctuation, make the heading distinct, keep body text readable and use spacing consistently. Avoid using multiple spaces to force text into position; use the application's alignment and paragraph controls.
\section{Naming and saving files}
A filename should help another person identify the document without opening several files. A practical pattern is \texttt{Class9\_EventNotice\_Draft1}. Use a name that suits the school's agreed convention and avoid vague names such as \texttt{newfile} or \texttt{finalfinal}. Save in the required folder. Then close and reopen the file; this confirms that the document was saved where expected.
\section{Formatting for readers}
Use headings to show structure, not just to decorate. Keep font choices limited, use a consistent hierarchy, and leave enough white space for the eye to follow the page. Check that the document remains readable when viewed at ordinary screen size or printed. Colour should support meaning and should not be the only way information is distinguished.
\section{Troubleshooting without panic}
If a file seems to have disappeared, first check the current folder, recent files list and filename. Avoid creating several copies immediately, because this can make the situation more confusing. If formatting changes unexpectedly, undo the last action if appropriate and inspect paragraph or style settings. If the program closes unexpectedly, follow the application's recovery process and then save a clearly named copy.

\section{What the trainer should observe}
Look for a sensible sequence, not just a polished page. Can the learner explain why they chose the filename? Did they check the source text? Did they save in the correct location? Can they retrieve the file without assistance? These observations show whether the skill is likely to transfer to a new task.



\chapter{Unit 4 -- Spreadsheets and Data Quality}
\section{Understanding a worksheet}
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/spreadsheet_cells.png}{\includegraphics[width=.82\textwidth]{../Domestic data entry operator-9th/book_illustrations/spreadsheet_cells.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: spreadsheet cells}}\end{center}}\end{center}
A worksheet organises information in rows and columns. A cell is identified by its column letter and row number, such as B3. A range is a group of cells. Before entering data, learners should identify the purpose of each column and use clear headings. One row usually represents one record; each column should hold one type of information. This makes the table easier to check, sort and summarise.
\section{Enter data consistently}
Use fictional inventory data for a school computer lab. Suggested columns are Asset ID, Item, Quantity, Condition and Last Checked. Show how to enter one row, then ask learners to complete the rest. Dates should use a consistent format. Quantity should be entered as a number, not as a mixture of words and digits. Required values should be checked against the source, not guessed.
\section{Basic calculations and verification}
Where the prescribed learning outcomes include formulas, demonstrate a simple total using a small number of values. Explain the range included in the formula and verify the result independently. A formula can produce a plausible answer even when it points to the wrong cells. Test the formula with a small example or recalculate the total manually before trusting it.
\section{Find common data-quality issues}
Typical issues include duplicate identifiers, blank required fields, inconsistent spelling, mixed date formats, numbers stored as text and values that do not fit the expected range. Give learners a worksheet with deliberate errors. Ask them to locate each issue, explain why it matters and identify the correct source for resolution. Do not reward learners for silently filling in missing values from guesswork.
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/data_quality_cycle.png}{\includegraphics[width=.78\textwidth]{../Domestic data entry operator-9th/book_illustrations/data_quality_cycle.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: data quality cycle}}\end{center}}\end{center}
\section{Sorting, filtering and protecting the record}
If sorting or filtering is part of the prescribed software practice, show the class how to select the full table before sorting. Sorting only one column can detach values from their records. Use a copy of the practice file before experimenting. Ask learners to check that each ID remains with its original item after the sort. Save a new version when the activity calls for a substantial change.
\section{A realistic classroom case}
A lab assistant gives the class an inventory sheet with ten assets. Two assets have the same ID, one quantity is blank, and three dates use different formats. Learners should first compare the worksheet with the original sheet, mark the issues and write a question for the supervisor about the missing quantity. They then correct only the errors supported by the source. The class finishes by explaining why the duplicate ID is more serious than a minor spacing inconsistency.



\chapter{Unit 5 -- Digital Presentations}
\section{Plan before opening the software}
A presentation should help an audience understand a message. Before creating slides, ask: who will listen, what should they understand, and what should they do with the information? A short classroom presentation usually needs a beginning, a small number of supporting points and a clear ending. Adding slides is not the same as adding useful information.
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/presentation_sequence.png}{\includegraphics[width=.82\textwidth]{../Domestic data entry operator-9th/book_illustrations/presentation_sequence.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: presentation sequence}}\end{center}}\end{center}
\section{Build a readable slide}
Use a clear title, short phrases and a visual that supports the message. Keep alignment and typography consistent. If the text is too small to read from the back of the room, reduce the content or split it across slides. Avoid unnecessary transitions and decorative effects that compete with the information. A simple slide that the audience can follow is usually more effective than a crowded one.
\section{Use images responsibly}
Choose visuals that are relevant and suitable for the audience. Credit or follow the reuse conditions of external images when required. Do not include a photograph of a student, customer or colleague without the appropriate permission. For practice, use original shapes, approved school assets or clearly reusable images.
\section{Review from the audience's seat}
Run the slideshow and check it in presentation mode. Ask a peer to sit at a distance and report which words are difficult to read. The presenter should practise explaining the slide rather than reading every word. Feedback should be concrete: “The diagram explains the sequence well, but the last line is too small,” is more useful than “Make it better.”



\chapter{Unit 6 -- Lesson Planning and VT Microteaching}
\section{Start with the learner's outcome}
A lesson outcome should describe what the learner can demonstrate by the end. “Understand spreadsheets” is too broad to observe. “Enter six fictional inventory records, identify a duplicate ID and explain how it should be resolved” gives the trainer and learner a shared target. Choose an outcome that fits the available time and equipment.
\section{Plan the lesson sequence}
A practical session can follow this structure: connect to a familiar situation, state the outcome, demonstrate the task, guide the first attempt, provide independent practice, check the work and close with reflection. Do not spend the entire period explaining. Learners need enough time to handle the keyboard, make decisions and recover from ordinary mistakes.
\begin{center}\IfFileExists{../Domestic data entry operator-9th/book_illustrations/teaching_cycle.png}{\includegraphics[width=.78\textwidth]{../Domestic data entry operator-9th/book_illustrations/teaching_cycle.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: teaching cycle}}\end{center}}\end{center}
\section{Microteaching in small steps}
Ask each VT to teach a short section to peers acting as learners. The task should be narrow enough to demonstrate in five to eight minutes. The observer records whether the outcome was clear, the steps were visible, the explanation used accessible language, learners were invited to practise, and the final check matched the outcome. The purpose is rehearsal, not performance theatre.
\section{Giving peer feedback}
Use a simple structure: one thing that helped learning, one point that could be clearer, and one practical suggestion. Base comments on observed behaviour. “You showed how to save and then reopened the file to verify it” identifies a useful practice. “You are a natural teacher” may be kind, but it does not tell the VT what to repeat next time.
\section{Adapting when the plan changes}
If computers are unavailable, use printed screenshots or a step-card sequence to discuss decisions, then schedule hands-on practice as soon as possible. If the class needs more time, preserve the core outcome and shorten optional extension work. If the activity is too easy, add a realistic checking challenge rather than merely increasing the amount of typing.



\chapter{Unit 7 -- Assessment, Feedback and Learning Records}
\section{Match assessment to the skill}
If the outcome is to create and save a document, a written quiz alone is not enough. Ask the learner to perform the task and show the saved file. If the outcome is to identify data-quality problems, provide a small table and ask the learner to mark the issues and explain the next step. Evidence should reflect the actual skill being taught.
\section{Use a short, visible rubric}
A rubric should describe observable performance. Avoid vague criteria such as “good work” or “excellent understanding.” For a document task, criteria might include: required content present, readable formatting, meaningful filename, correct save location and successful retrieval. Explain the criteria before practice so learners know what quality looks like.
\begin{center}\small\begin{tabularx}{\textwidth}{|p{.27\textwidth}|X|X|}\hline
\textbf{Criterion} & \textbf{Independent} & \textbf{Needs another practice}\\\hline
Task sequence & Completes steps in a sensible order & Misses or repeats important steps\\\hline
Accuracy & Checks output against the source & Several unchecked mismatches remain\\\hline
File handling & Saves and retrieves the correct file & Cannot locate the saved result\\\hline
Explanation & Can explain at least one quality check & Cannot yet explain how correctness was checked\\\hline
\end{tabularx}\end{center}
\section{Feedback while the task is fresh}
Feedback works best when it is prompt, specific and possible to act on. Name the observed behaviour, explain its effect and agree on the next step. For example: “You checked the first five rows, but the final two were not compared with the source. Before submitting the next sheet, scan every row and mark the ones you have verified.” Avoid comparing one learner's result with another learner's result when the useful comparison is with the task criteria.
\section{Keep records responsibly}
Record only the information needed for teaching and assessment. Store records in the authorised place and share them only with people who have a legitimate reason to see them. Follow the school's retention and reporting requirements. Do not put learner scores or personal details in public chat groups or on an open display. If an error is found in a record, correct it through the agreed process and preserve any required audit trail.



\chapter{Unit 8 -- Digital Safety, Privacy and Professional Conduct}
\section{Use fictional data for practice}
A classroom exercise rarely needs real addresses, phone numbers, identification numbers or marks. Use clearly fictional data instead. If a real record must be used under an approved school process, follow the required permissions, access controls and storage rules. Never copy sensitive information into a personal device or unapproved cloud service merely because it is convenient.
\section{Account and device habits}
Use individual accounts where available, keep passwords private and lock the screen when leaving a shared computer. Do not ask learners to reveal their passwords to prove they can sign in. Follow the institution's process for password resets. Keep software and security controls in place as directed by the responsible administrator, and do not install unapproved applications on school devices.
\section{Email, links and unexpected requests}
Pause before opening an unexpected attachment or entering a password after following a link. Check the sender and the context, and use a known route to contact the organisation if a request seems unusual. A message that creates urgency or asks for confidential data deserves extra care. Teach learners to report suspicious messages rather than forward them to classmates.
\section{Safe file sharing}
Before sharing a file, check the recipient, the contents and the permission level. A document intended for one teacher should not be placed in a folder that everyone can access. Use approved storage and remove access when it is no longer required, following the local procedure. Avoid sending sensitive records to a personal email account.
\section{Professional conduct}
Data-entry work involves trust. A professional operator does not guess missing information, share records out of curiosity, hide an error, or use information for personal reasons. If something seems wrong, stop and ask the authorised person. Explain to learners that reporting an error early is usually safer than quietly trying to conceal it.

\chapter{Introduction to Styles}
\section{Why styles matter}
A long document is easier to maintain when similar parts share the same formatting. A heading style can keep chapter titles consistent; a body-text style can keep paragraphs readable; and a caption style can give every figure the same treatment. Manual formatting changes one selection at a time. Styles record a set of choices so the same visual rule can be applied repeatedly and updated centrally.
A style is a named collection of formatting properties. Consistent styles improve readability and make automatic navigation features possible.
\section{Main style categories}
Paragraph styles control complete paragraphs, including spacing and alignment. Character styles format selected words or characters. Page styles govern the page layout, margins, orientation, headers and footers. Frame styles format containers that may hold text or pictures. List styles control bullets and numbering, while table styles organise the appearance of tables. Use the category that matches the item being formatted.
\begin{center}\IfFileExists{../Domestic data entry operator-10th/book_illustrations/style_categories.png}{\includegraphics[width=.83\textwidth]{../Domestic data entry operator-10th/book_illustrations/style_categories.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: style categories}}\end{center}}\end{center}
\section{Applying a built-in style}
Open a document and select the heading that needs formatting. Open the Styles panel from the menu or use the keyboard shortcut available in the installed version. Choose the paragraph-style category and apply an appropriate heading style. Repeat for other headings instead of formatting each one independently. For a longer report, check several pages to confirm that headings of the same level look alike.
\section{Creating and updating styles}
To create a custom style, first format a sample paragraph as required, then use the option to create a style from the selection. Give the style a meaningful name, such as \texttt{SectionHeading}. If a style already exists but needs a change, adjust a representative paragraph and use the update-style command. Test the change on more than one section before relying on it throughout a document.
\section{Templates and page layout}
A template is a starting document that contains reusable layout and style choices. Loading styles from another file can help maintain a consistent look, but it is sensible to test the result on a copy first. Page styles control margins, paper orientation, header/footer placement, background and borders. Use portrait pages for ordinary reports; landscape may be useful for a wide table.
\section{Common errors}
A heading that only looks bold is not necessarily a real heading style. This can prevent it appearing in a table of contents. Repeated spaces used for alignment may shift when fonts or page sizes change. Inconsistent page styles can create unexpected blank pages or different margins. Correct the underlying style rather than patching each occurrence individually.
\section{Chapter questions}
\begin{enumerate}\item What is a style, and why is it useful in a long document?\item Distinguish paragraph, character and page styles.\item How can a custom style be created from a formatted selection?\item Why should headings use heading styles when a table of contents is required?\item Give two examples of formatting problems caused by manual formatting.\end{enumerate}

\section{Choosing the right image}
Images can explain a process, identify an object or make a document easier to scan. A picture should support the nearby text rather than simply fill space. For an office report, a small labelled diagram may be clearer than a decorative photograph. Confirm that an image is appropriate to the subject and that its licence or permission allows the intended use.

Place the cursor near the paragraph that introduces the image, then use the insert-image option. Resize from a corner handle where available so the original proportions are preserved. Cropping removes unwanted outer portions without changing the message of the remaining image. \chapter{Analyse Data Using Scenarios and Goal Seek}
\section{What-if analysis}
A spreadsheet model contains input values and formulas that calculate results. What-if analysis explores how the result changes when one or more inputs change. A scenario stores a group of assumptions, such as a low, expected or high estimate. Scenarios are useful for comparing possibilities; they do not predict which possibility will actually occur.
\begin{center}\IfFileExists{../Domestic data entry operator-10th/book_illustrations/scenario_goal_seek.png}{\includegraphics[width=.83\textwidth]{../Domestic data entry operator-10th/book_illustrations/scenario_goal_seek.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: scenario goal seek}}\end{center}}\end{center}
\section{Build a small model}
Imagine a school event budget with planned attendance, cost per participant and a fixed venue charge. Total cost can be calculated from the assumptions. Keep input cells clearly separated from formula cells and label units. Before comparing scenarios, confirm that each one changes the intended cells and that the formula uses the correct references.
\section{Using Goal Seek}
Goal Seek works backwards from a desired formula result to estimate the input value that would achieve it. Select the formula cell as the target, specify the desired value and identify the input cell the application may change. Review the returned value and confirm that the model is logical. It solves the selected relationship; it does not prove the assumptions are realistic.

Test a simple case manually. Confirm that changing one input affects the expected outputs and that the target cell contains a formula. Save a separate copy before experimenting with a complex model. \chapter{Linking Spreadsheet Data}
\section{Why link data?}
A workbook may contain related information on different sheets, or a report may need data from another file. Linking avoids typing the same values repeatedly, but it introduces a dependency: if the source moves or is unavailable, the link may not update as expected. Decide which file is authoritative and keep an understandable folder structure.
\section{References between sheets}
A cell reference points to a location in a worksheet. A formula can refer to another sheet so a summary uses the original record. Use descriptive sheet names and clear headings. External links may ask whether to update values when a workbook opens. Update only when the source is trusted and expected. \chapter{Introduction to Database Management System}
\section{From files to a database}
A database is an organised collection of related data. A Database Management System (DBMS) helps create, store, retrieve and maintain that data. A paper register or separate files can work for a small task, but duplicate records and inconsistent updates become harder to manage as the information grows. A database can enforce rules and connect related information in a structured way.
\begin{center}\IfFileExists{../Domestic data entry operator-10th/book_illustrations/database_relationships.png}{\includegraphics[width=.86\textwidth]{../Domestic data entry operator-10th/book_illustrations/database_relationships.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: database relationships}}\end{center}}\end{center}
\section{Tables, fields and records}
A table stores one kind of entity, such as students, books or issued items. A field is a column describing an attribute; a record is one row describing an instance. For a library table, fields might include BookID, Title and Category. Choose data types that match the values, and avoid putting unrelated details into one field if they need to be searched or validated separately.
\section{Keys and relationships}
A primary key uniquely identifies each record. A foreign key stores a value that refers to a record in another table. Relationships reduce the need to repeat the same facts. In a library example, a Books table can be related to an Issues table through BookID. Referential integrity helps prevent a related record from pointing to a key that does not exist, subject to the design and rules configured in the database.
\section{Database models}
A relational database represents data in related tables. Other models organise relationships differently. For introductory office work, the relational model is particularly useful because tables, keys and queries can be explained with familiar records. Good design begins with understanding what each record represents and which facts belong together.

\chapter{Starting with LibreOffice Base}
\section{Database objects}
LibreOffice Base is a database front end that can work with different database arrangements. Depending on the chosen database type, a file may store data directly or connect to an external database engine. The main objects commonly introduced are tables, queries, forms and reports. Each serves a different purpose: tables store records, queries select or calculate information, forms support data entry, and reports present organised output.
\section{Creating a new database}
Start a new database from the application and follow the wizard for the required database type. Save it in the intended practice folder with a meaningful filename. Create a small table with fields such as AssetID, ItemName, Quantity and Condition. Select suitable data types and designate a unique field as the primary key where appropriate. Reopen the file to ensure the saved database is accessible.
\section{Data types and validation}
Text fields store names and codes; numeric fields store quantities or measurements; date fields store dates; and Boolean fields represent a true/false condition. A code that contains leading zeros may need to be stored as text so the zeros are preserved. Decide which fields may be blank and which should be required. Validation rules help reduce errors at the point of entry.
\section{Enter and inspect records}
Add a few fictional asset records, then navigate between rows and edit one value. Check that the changed value appears in the intended field. Try leaving a required field blank if the rule permits testing, then observe the validation response. Keep a clean copy before performing experiments that may affect the table structure.

\chapter{Working with Multiple Tables}
\section{Avoiding repeated facts}
If an office stores a person's details in every transaction row, the same name or address may be repeated many times. Updating one row but missing another creates inconsistency. Separate tables can store the entity once and link other records to it by a key. The right structure depends on the information and the questions users need to answer.
\section{Relationships and integrity}
A one-to-many relationship occurs when one record in a table relates to several records in another. For example, one customer may have many orders. The foreign key in the order table points to the customer key. Relationship rules should prevent invalid links and should consider what happens if a referenced record is updated or deleted. Do not delete a record without understanding its linked records and the organisation's retention needs.
\section{Plan tables before creating them}
List the entities, their attributes and the unique identifier for each. Draw the relationships and identify which table contains the foreign key. Then create the tables and test with a small set of records. If a value appears repeatedly in several records, ask whether it belongs in a separate related table.

\chapter{Queries in Base}
\section{What a query does}
A query asks the database for a subset or calculated view of its data. It can select records matching conditions, choose particular fields, sort results and combine related tables. A query normally does not replace the underlying source table; it describes which information to retrieve. The exact design interface depends on the selected database and version.

\section{Criteria and sorting}
Suppose the asset register contains equipment in several conditions. A query can show only records whose Condition is “Needs Repair,” or sort all assets by ItemName. Criteria should match the field's data type. A date condition should use a valid date value, while text criteria need the correct spelling and should account for how the database handles case and spaces.
\section{Queries involving several tables}
A join connects related records through matching keys. When joins are incorrect, the output may omit records or multiply rows unexpectedly. Check that the joined fields represent the same type of identifier and that the relationship is correct. Use a small test with known records to verify the results.
\section{Queries and privacy}
A query can expose information even if the user does not open the original table directly. Return only fields needed for the task and share results with authorised recipients. Do not create broad exports containing personal information when a smaller summary would meet the requirement.

\chapter{Health, Safety and Security at Workplace}
\section{Recognising workplace risks}
Computer-based work can involve physical, environmental and information-security risks. Poor workstation setup may contribute to discomfort; clutter can create trip hazards; exposed electrical equipment can cause serious injury; and weak information handling can expose private records. Risk management starts by recognising hazards, considering who may be harmed and following the organisation's procedures.
\begin{center}\IfFileExists{../Domestic data entry operator-10th/book_illustrations/healthy_workstation.png}{\includegraphics[width=.83\textwidth]{../Domestic data entry operator-10th/book_illustrations/healthy_workstation.png}}{\begin{center}\fbox{\parbox[c][28mm][c]{.76\textwidth}{\centering\small Illustration not available in this build: healthy workstation}}\end{center}}\end{center}
\section{Ergonomics and eye comfort}
Arrange the chair, monitor, keyboard and mouse to suit the user and the task. Keep the screen readable and reduce distracting reflections. Change position periodically and take short visual breaks during extended work. If a person experiences persistent pain or eye discomfort, they should report it and seek appropriate professional advice rather than treating a textbook as medical guidance.
\section{Stress and work organisation}
Long periods of intense work, unclear instructions and constant interruptions can increase strain. Divide work into manageable tasks, clarify priorities and ask for assistance when a deadline conflicts with the expected quality. A realistic pace supports both wellbeing and accurate data handling. Supervisors should encourage reporting concerns early rather than rewarding unsafe shortcuts.
\section{Electrical and physical safety}
Keep liquids away from electrical equipment and do not handle plugs or devices with wet hands. Do not attempt repairs unless authorised and trained to do so. Keep walkways clear, route cables safely and report damaged equipment. Follow local procedures for ventilation, lighting, noise and equipment placement.
\section{Information security at a workstation}
Lock the screen when leaving a shared computer, use approved accounts and keep passwords confidential. Do not install unauthorised software or connect unknown devices. Confirm the recipient before sending a file and follow access rules for personal information. Physical safety and information security are both part of a responsible workplace.

\chapter{Workplace Quality Measures}
\section{Quality is built into the process}
Quality work meets the stated requirement reliably, not just quickly. For data entry, this means using the correct source, entering values in the intended fields, checking completeness and protecting records. A quality process makes the expected standard visible and gives people a way to identify and correct errors.
\section{Checks before submission}
A final review can include a field-by-field comparison with the source, checking required fields, identifying duplicates, confirming date and number formats, and verifying that the file is saved in the correct place. The amount of checking should reflect the task's risk. High-impact records deserve careful review and the required approval.

When an error cannot be resolved from the available source, mark it for follow-up and identify the appropriate person or process. Do not silently substitute a plausible value. If the same error occurs repeatedly, look for a process cause. The instruction may be unclear, a form may invite mistakes, or a field may lack a useful validation rule. A small change to the process can prevent many corrections later. Test the change and confirm that it improves quality without creating a new problem.

Raise the alarm and contact the designated emergency service or internal response team according to local procedure. Do not attempt a rescue that places you or others at further risk.
\section{After the event}
Once safe, report what happened through the appropriate channel. Record objective facts rather than guesses about the cause. Participate in the review process if asked and help identify practical steps that may reduce the chance of recurrence. Incident reports should be handled carefully and shared only with authorised people.

\chapter{Web Design and Development}
A website often begins with a simple question: what should people be able to find or do here? The answer shapes every decision that follows, from the first sketch of a page to the code that runs in a browser. Good web design helps visitors understand where they are and what they can do next. Good development turns that plan into a working site, checks that it behaves properly, and makes it dependable on different devices.

The two activities work best together. A page may look attractive but still frustrate people if its navigation is confusing or its text is difficult to read. Likewise, a technically correct page is not very useful if visitors cannot find the information they came for. A thoughtful developer keeps the people using the website in mind while planning, designing, coding, testing, and improving it.

\section{Understanding Web Design}
Web design concerns the organisation and presentation of information on a website. It includes page layout, colour, typography, images, navigation, spacing, and the way a visitor moves from one task to another. Good design makes the purpose of each page clear and helps users find what they need without unnecessary effort.

A designer begins by asking who will use the website, what those people need to do, and what information they expect to find. A school website, for example, may need clear links to admissions, courses, notices, and contact details. An online shop needs product information, prices, search and filtering, a cart, and a clear checkout path. The design should reflect the real purpose of the site rather than decorative trends alone.

\subsection{User Interface and User Experience}
The user interface (UI) is the part of the system with which a person interacts: menus, buttons, links, forms, headings, and visual controls. User experience (UX) is the broader experience of using the site, including how easy it is to learn, how quickly a task can be completed, and whether the process feels predictable and trustworthy.

A visually attractive interface can still provide a poor experience if its navigation is confusing or its forms give unclear errors. Similarly, a simple interface can provide a strong experience when the content is well organised, controls are labelled clearly, and users receive helpful feedback after an action.

\section{Understanding Web Development}
Web development is the process of building and maintaining the website's structure, appearance, behaviour, and supporting services. Front-end development creates the part that runs in the browser. HTML describes the content and its meaning, CSS controls presentation and layout, and JavaScript adds behaviour such as menu interaction, input validation, and dynamic updates.

Back-end development, when required, handles server-side tasks such as business rules, user authentication, data storage, and communication with other services. A database stores information in an organised form. An application programming interface (API) can provide a defined way for the browser or another application to request data or perform an operation. A small static information site may not need a back end; a learning portal with student accounts and saved results usually does.

\subsection{Static and Dynamic Websites}
A static website serves pages whose content is mainly prepared in files such as HTML, CSS, JavaScript, and images. It is suitable for portfolios, simple information pages, event announcements, and small documentation sites. A dynamic website can change its output based on user input, stored data, permissions, or other conditions. Examples include online banking, booking systems, shopping sites, and student portals.

The distinction is about how the content is produced, not whether the page has styling or animation. A static page can be visually rich and interactive in the browser. A dynamic service often combines browser code with server-side processing and a database.

The development life cycle provides a sequence of activities that helps a team move from an idea to a reliable website. The stages may overlap, and teams often return to earlier decisions after testing or feedback. The purpose of a life cycle is not to create paperwork for its own sake; it is to reduce avoidable mistakes, make decisions visible, and ensure that the final site meets its requirements.

\subsection{Stage 1: Discover the Need}
Identify the problem the website should solve and the people who will use it. Gather information from stakeholders, review existing material, and list the most important user tasks. For a school information site, these tasks may include finding a course, checking an announcement, or contacting the office. Clear goals prevent the project from becoming a collection of unrelated pages.

\subsection{Stage 2: Plan the Work}
Define the scope, deliverables, schedule, resources, and responsibilities. Decide which features are essential for the first version and which can wait. A page list and a simple task board can be sufficient for a small project. Planning should also consider risks such as missing content, unavailable images, device compatibility, privacy, and limited time.

\subsection{Stage 3: Design the Structure and Appearance}
Create a sitemap to show how pages relate to one another. Sketch wireframes to decide where headings, navigation, content, forms, and images should appear. Choose a consistent colour palette, type scale, spacing system, and button style. Review the design against the user tasks before investing time in detailed implementation.

\subsection{Stage 4: Develop the Website}
Build the page structure with semantic HTML, apply CSS for layout and responsive behaviour, and add JavaScript where interaction is needed. Keep files organised and use meaningful names. Work in small steps: create a page shell, check it in a browser, add one feature, and test again. This makes it easier to identify which change introduced a problem.

\subsection{Stage 5: Test and Review}
Testing checks whether the site behaves as intended. Confirm that links work, forms handle missing or invalid values, images load, text is readable, and the layout works on narrow and wide screens. Use keyboard navigation and inspect error messages in the browser's developer tools. Fix serious problems before publishing, then repeat the relevant tests after changes.

\subsection{Stage 6: Publish and Deploy}
Publishing makes the site available to its intended audience. Deployment may involve uploading static files to a hosting service, connecting a domain name, enabling HTTPS, configuring server settings, and checking that all paths work on the live site. A site that works on a developer's computer can still fail after deployment if file names, capitalisation, paths, permissions, or environment settings differ.

\subsection{Stage 7: Maintain and Improve}
After release, check for broken links, outdated information, security updates, performance problems, and user feedback. Keep a copy of the source files and a record of important changes. Maintenance is part of development, not an optional activity that begins only when something breaks.

\section{Core Principles of Effective Web Design}
\subsection{Visual Hierarchy}
Visual hierarchy helps readers recognise what is most important. Main headings should be more prominent than body text; related items should be grouped; and primary actions should be easy to identify. Use size, weight, spacing, alignment, and colour consistently. Avoid giving every element the same visual emphasis, because this makes it harder to scan a page.

\subsection{Consistency and Simplicity}
Use the same navigation pattern, heading styles, button shapes, and spacing rules across related pages. Consistency reduces the effort required to learn the site. Simplicity does not mean removing necessary information; it means presenting the information in a clear order and avoiding decoration that competes with the task.

\subsection{Colour and Typography}
Choose colours that support the site's purpose and provide sufficient contrast between text and its background. Do not communicate important status using colour alone; pair colour with a label or icon where appropriate. Use a small, consistent set of readable fonts and line lengths. Body text should remain comfortable to read on both desktop and mobile displays.

\subsection{Navigation and Content}
Navigation labels should describe their destination, for example, “Courses” or “Contact”, rather than vague labels such as “Click here”. Put frequently used destinations where people expect them. Write concise headings, divide long material into meaningful sections, and ensure that images have a clear purpose. Content should answer the questions visitors came to resolve.

\section{Responsive Design and Device Support}
A responsive website adapts its layout to the available screen space. A multi-column desktop layout may become a single column on a phone; navigation may wrap or collapse; images should scale without distortion; and buttons should remain large enough to tap comfortably. Responsive design uses flexible layouts, relative sizing, and CSS media queries rather than building an entirely separate page for every device.

\section{Accessibility and Inclusive Design}
Accessible design allows people with different abilities and ways of interacting to use a website. Provide meaningful headings, labels for form controls, alternative text for informative images, sufficient colour contrast, and visible keyboard focus. Ensure that interactive elements can be reached and operated without a mouse. Plain, direct language also helps users who are new to the subject or reading in a second language.

Accessibility is best considered during planning and design, then checked throughout development. Retrofitting it at the end may require changing page structure and interaction patterns. A practical review includes keyboard-only navigation, zooming text, checking labels, and verifying that the purpose of each link is understandable.

\section{Designing for Quality, Security and Performance}
Quality includes correctness, usability, reliability, maintainability, accessibility, and performance. Optimise images so that they are not unnecessarily large, avoid loading resources that are not needed, and test pages on a realistic connection. Keep dependencies and source files organised so another developer can understand the project.

Security must also influence design decisions. Collect only the information the site actually needs, explain why it is collected, and avoid placing passwords, private keys, or secret tokens in front-end code. Use HTTPS for deployed sites and apply appropriate validation and access controls when server-side features are involved. A polished interface cannot compensate for unsafe handling of user data.

\section{Example: Planning a Learning Centre Website}
Consider a learning centre that needs to publish courses, class schedules, announcements, and contact information. Before coding, the team identifies the main visitors: learners, parents, and staff. The essential pages are Home, Courses, Notices, and Contact. The home page introduces the centre and links to the most common tasks; the courses page provides names, descriptions, and eligibility information; the notices page lists dated updates; and the contact page gives verified contact details.

The first version can be a static website if the information is updated manually. If staff later need to sign in and manage notices, the project may require authentication, a server, and a database. This illustrates an important planning rule: begin with the simplest solution that satisfies the confirmed need, then add complexity only when a real requirement justifies it.

\chapter{Requirements, Planning and Project Documents}
\section{Understanding the Need}
A web project begins by understanding the problem it is expected to solve. A website for a school, a small shop, a public service office, and an online learning platform may all use a browser, but each has different users, content, rules, and success measures. Clear requirements prevent avoidable rework and help a team agree on what must be delivered.

\subsection{Stakeholders and Users}
A stakeholder is a person or group affected by the project. Stakeholders may include the customer, website visitors, content editors, administrators, support staff, and the organisation responsible for maintaining the site. Users should be described by their goals rather than by assumptions about their age, device, or technical knowledge.

\subsection{Functional and Non-functional Requirements}
Functional requirements describe what the system must do: display a product catalogue, validate a form, search for an article, or allow an authorised editor to update content. Non-functional requirements describe qualities and constraints, such as response time, accessibility, security, browser support, reliability, and ease of maintenance.

\midrule

\section{Brief Requirements Document}
A simple project brief should record the purpose, target audience, main pages, required functions, content owner, constraints, and acceptance criteria. Acceptance criteria are observable conditions used to decide whether a feature is complete. For example, “the contact form is finished” is vague; “the form identifies missing required fields and displays a clear confirmation after valid submission” is testable.

\section{Planning and Scope}
Scope defines what is included and what is excluded. A small first release may include a home page, about page, services page, and contact form. A payment system or user account feature may be planned for a later release. A scope list helps the team manage time and avoid adding unplanned work without reviewing its impact.


\section{Business and Software Requirements}
A Business Requirements Document (BRD) describes the business need, intended users, goals, scope, constraints, and expected outcomes. A Software Requirements Specification (SRS) translates the agreed need into detailed system behaviour, interfaces, data requirements, and quality expectations. These documents should be clear enough that a developer can implement the work and a tester can verify it.

A practical BRD may contain the problem statement, project objectives, stakeholders, scope, assumptions, constraints, risks, and acceptance criteria. An SRS may describe functional requirements, non-functional requirements, input and output formats, error handling, external interfaces, and security expectations. For a small classroom project, these can be concise documents rather than lengthy reports.

\section{High-Level and Low-Level Design}
High-level design (HLD) describes the major components of a solution and how they communicate. For a website, it may show the browser interface, application server, database, and external services. Low-level design (LLD) describes the details needed to implement a component, such as field names, validation rules, function responsibilities, or the structure of a page.

Object-oriented design organises a system around objects that combine data and behaviour. Database design identifies the information that must be stored and the relationships between records. API design defines how separate software components exchange requests and responses. The chosen design should match the project size and should not introduce complexity without a clear need.

\chapter{Web Technologies, Browsers and HTTP}
\section{How a Web Page Reaches a Browser}
When a visitor enters a website address, the browser uses network services to locate the destination server and request resources. The server returns a response, often containing HTML, CSS, JavaScript, images, fonts, or data. The browser interprets these resources and constructs the visible page. This process may involve many requests rather than a single file.

\section{HTTP and HTTPS}
HTTP is a protocol used for communication between clients and web servers. A request commonly identifies a method, a resource path, headers, and sometimes a body. A response contains a status code, headers, and usually content. HTTPS protects HTTP communication using TLS, helping protect data from interception or alteration while it travels across the network.

\subsection{Common Status Codes}
\begin{itemize}
\item \textbf{200 OK:} The request was processed successfully.
\item \textbf{301 or 302:} The resource has been redirected.
\item \textbf{400 Bad Request:} The server could not process the request as sent.
\item \textbf{401 Unauthorized:} Authentication is required or has not succeeded.
\item \textbf{403 Forbidden:} The server refuses access to the requested resource.
\item \textbf{404 Not Found:} The requested resource could not be found.
\item \textbf{500 Internal Server Error:} The server encountered an unexpected condition.
\end{itemize}

\section{Browser Developer Tools}
Developer tools help inspect HTML elements, view computed CSS, monitor network requests, read console messages, and test responsive layouts. They are useful for learning because a developer can change a style temporarily, observe the result, and then apply a tested correction to the source code.


\section{Development Tools and Standards}
A web developer commonly uses a code editor, browser, developer tools, image editor, version-control system, and a local testing environment. A code editor helps organise files and detect syntax mistakes; a browser displays the result; developer tools help investigate layout, script, and network problems; and version control records changes so that earlier working versions can be recovered.

HTML, CSS, and JavaScript are interpreted by browsers according to web standards. Consistent indentation, meaningful file names, and a clear folder structure make a project easier to review. A small site might use \texttt{index.html}, \texttt{styles.css}, \texttt{script.js}, and an \texttt{images} folder. Keep source files separate by responsibility unless a particular platform requires another structure.

\section{Common Application Development Models}
The Waterfall model organises work into sequential phases such as requirements, design, implementation, testing, and maintenance. It can be straightforward when requirements are stable, but changes discovered late may be expensive. The Iterative model develops a solution through repeated cycles, refining it after feedback. Agile approaches organise work into small increments and encourage frequent collaboration, review, and adaptation.

No single model is best for every project. A small student website may be planned with a simple checklist and improved after each review. A regulated or large system may need formal documentation and approval steps. The useful question is whether the chosen process helps the team deliver the required quality while responding appropriately to change.

\chapter{Semantic HTML and Accessible Structure}
\section{Meaningful HTML Elements}
Semantic HTML uses elements that communicate the role of content. Elements such as \texttt{header}, \texttt{nav}, \texttt{main}, \texttt{article}, \texttt{section}, and \texttt{footer} provide more meaning than using generic containers for every part of a page. Clear structure can improve maintainability and help assistive technologies interpret the document.

\begin{lstlisting}[style=webcode,language=HTML]
<header>
  <h1>Community Learning Centre</h1>
  <nav aria-label="Main navigation">
    <a href="#courses">Courses</a>
    <a href="#contact">Contact</a>
  </nav>
</header>
<main>
  <section id="courses">
    <h2>Available courses</h2>
    <p>Explore the current learning options.</p>
  </section>
</main>
<footer>
  <p>Contact the centre for further information.</p>
</footer>
\end{lstlisting}

\section{Headings and Content Hierarchy}
Headings should describe the topic beneath them and follow a logical hierarchy. A page usually has one main heading, followed by section headings and, where necessary, subheadings. Heading levels should not be selected merely to obtain a desired font size; visual appearance belongs in CSS, while the heading element communicates structure.


\section{Lists and Grouped Information}
HTML supports ordered lists, unordered lists, and description lists. Use an unordered list when the order does not matter, such as a list of required materials. Use an ordered list when the sequence matters, such as installation steps. A description list can pair terms with their explanations.

\begin{lstlisting}[style=webcode,language=HTML]
<h2>Preparation checklist</h2>
<ul>
  <li>Open the code editor.</li>
  <li>Create a project folder.</li>
  <li>Save the first HTML page.</li>
</ul>

<h2>Development sequence</h2>
<ol>
  <li>Plan the page.</li>
  <li>Build the structure.</li>
  <li>Test the result.</li>
</ol>
\end{lstlisting}
Nested lists are useful when a main item has related sub-items, but deep nesting can make information difficult to scan. Choose the list type according to the meaning of the content, not its default appearance.

\section{Links, Images and Alternative Text}
Link text should tell users what will happen when it is selected. Phrases such as “Read the admission requirements” are more informative than repeated “click here” links. Images that communicate information should have concise alternative text. Decorative images can use empty alternative text so that assistive technologies do not announce unnecessary details.

\section{Forms and Labels}
A form control should have a clear label. Placeholder text is not a replacement for a label because it disappears when the user enters a value and may be difficult to read. Required fields should be indicated clearly, and error messages should explain how to correct a problem.

\begin{lstlisting}[style=webcode,language=HTML]

  <label for="email">Email address</label>

</form>

\chapter{CSS Selectors, Cascade and Responsive Layout}
\section{Selectors}
CSS selectors identify the elements to which a rule applies. Element selectors target a tag name, class selectors target a reusable class, and ID selectors target an element with a specific identifier. Selectors should be chosen to make styles understandable and easy to maintain.

\begin{lstlisting}[style=webcode,language=CSS]
/* Element selector */
p { line-height: 1.6; }

/* Reusable class selector */
.notice {
  border-left: 4px solid #007F86;
  padding: 1rem;
}

/* Layout for a group of cards */
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1rem;
}
\end{lstlisting}

\section{Cascade, Specificity and Inheritance}
When more than one CSS rule can apply to an element, the cascade determines which declaration wins. Origin, importance, specificity, and source order affect the result. Inherited properties such as text colour may pass from a parent to its children, while properties such as margin do not normally inherit. Overusing highly specific selectors can make future changes difficult.

\section{Responsive Design}
Responsive design helps a layout adapt to different screen sizes. Flexible widths, relative units, CSS Grid, Flexbox, and media queries can be combined to create interfaces that work on phones, tablets, laptops, and larger screens. A responsive page should not merely shrink; content must remain readable and controls must remain usable.

\begin{lstlisting}[style=webcode,language=CSS]
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1rem;
}
@media (max-width: 700px) {
  .card-grid {
    grid-template-columns: 1fr;
  }
}
\end{lstlisting}

\section{Flexbox and Grid}
Flexbox is useful for arranging items along one primary axis, such as a navigation row. Grid is useful when a layout needs rows and columns together, such as a card gallery. Choosing the simpler layout model usually makes the code easier to understand.

\chapter{JavaScript Variables, Types and Operators}
\section{Storing Values}
Variables give names to values used by a program. JavaScript provides \texttt{const} for bindings that should not be reassigned and \texttt{let} for bindings that may change. \texttt{var} is part of the language but has different scoping behaviour and is usually avoided in new beginner examples.

\begin{lstlisting}[style=webcode,language=JavaScript]
const courseName = "Web Development";
let completedLessons = 3;
completedLessons = completedLessons + 1;

const isReady = completedLessons >= 4;
console.log(courseName, completedLessons, isReady);
\end{lstlisting}

\section{Common Data Types}
Strings represent text, numbers represent numeric values, booleans represent true or false, and arrays hold ordered collections. Objects group related properties. The value \texttt{null} can represent an intentional absence of a value, while \texttt{undefined} commonly indicates that a value has not been assigned or is missing.

\section{Operators and Comparisons}
Arithmetic operators perform calculations. Comparison operators produce Boolean results, and logical operators combine conditions. Strict equality (\texttt{===}) compares values without automatically converting different types, which makes it a good default for most comparisons.

\section{Readable and Safe Code}
Descriptive variable names, consistent indentation, and small expressions make code easier to review. Validate user-provided data before relying on it. Never treat browser-side validation as the only protection for a system that stores sensitive data; server-side checks are also required when a server is involved.

\chapter{Conditions, Loops, Functions and Arrays}
\section{Conditional Decisions}
Conditional statements allow a program to choose an action based on a condition. An \texttt{if}/\texttt{else} statement can validate input, choose a message, or control which content is shown. Conditions should be written clearly and tested for both expected and unexpected values.

\begin{lstlisting}[style=webcode,language=JavaScript]
const score = 76;
if (score >= 80) {
  console.log("Excellent");
} else if (score >= 50) {
  console.log("Pass");
} else {
  console.log("Needs more practice");
}
\end{lstlisting}

\section{Loops}
Loops repeat an operation while a condition is true or for each item in a collection. A loop needs a clear stopping condition; otherwise it may continue indefinitely. For arrays, methods such as \texttt{forEach}, \texttt{map}, and \texttt{filter} can express common operations when used appropriately.

\section{Functions}
A function groups instructions into a reusable unit. Parameters receive input, and a return value provides a result. Small functions are easier to test than one long block of mixed responsibilities.

\begin{lstlisting}[style=webcode,language=JavaScript]
function calculateAverage(values) {
  if (values.length === 0) return 0;
  const total = values.reduce((sum, value) => sum + value, 0);
  return total / values.length;
}
console.log(calculateAverage([70, 80, 90]));
\end{lstlisting}

\section{Arrays and Objects}
Arrays are suitable for ordered lists such as course names. Objects are suitable for related attributes such as a course title, duration, and level. Choosing an appropriate data structure reduces repetition and helps the program represent information clearly.


\section{Working with Strings}
A string is a sequence of text characters. JavaScript provides properties and methods for checking length, changing letter case, finding text, extracting a portion, and joining values. String methods usually return a result rather than changing the original string, so store the returned value when a change is needed.

\begin{lstlisting}[style=webcode,language=JavaScript]
const learner = "  Siva Sai  ";
const cleaned = learner.trim();
const greeting = "Welcome, " + cleaned + "!";
console.log(greeting);
console.log(cleaned.toUpperCase());
\end{lstlisting}
When processing names or messages, consider empty input and extra spaces. Do not assume that every text value is valid simply because it is a string; validation should match the purpose of the field.

\chapter{DOM, Events and Form Interaction}
\section{The Document Object Model}
The Document Object Model (DOM) represents a page as a tree of objects. JavaScript can select elements, read or update text, change classes, and respond to events. Changes should be made deliberately so that the page remains understandable and accessible.

\begin{lstlisting}[style=webcode,language=JavaScript]
const button = document.querySelector("#show-message");
const message = document.querySelector("#message");

button.addEventListener("click", () => {
  message.textContent = "Your action was received.";
});
\end{lstlisting}

\section{Events}
Events describe interactions such as clicks, keyboard input, form submission, and changes to a field. An event listener connects an event to a function. For forms, listening to the submit event makes it possible to validate data before displaying a result or sending a request.

\section{Validation and Feedback}
Good validation explains what needs correction. It should preserve user input where possible, identify the field with an issue, and avoid relying on colour alone to communicate errors. A successful action should also provide clear confirmation.

\section{Safe DOM Updates}
When displaying untrusted text, prefer \texttt{textContent} rather than inserting arbitrary HTML with \texttt{innerHTML}. This reduces the risk of interpreting user input as markup or script. More complex applications need additional security controls appropriate to their data and architecture.


\section{Drawing with the HTML Canvas}
The HTML \texttt{canvas} element provides a drawing surface that JavaScript can control. It is useful for simple charts, sketches, or interactive visual demonstrations. Canvas content is drawn with script and is not automatically exposed as ordinary text to assistive technology; provide a text explanation or an accessible alternative where the drawing conveys important information.

\begin{lstlisting}[style=webcode,language=HTML]
<canvas id="demo-canvas" width="320" height="140">
  A simple coloured rectangle illustration.
</canvas>
\end{lstlisting}

\begin{lstlisting}[style=webcode,language=JavaScript]
const canvas = document.querySelector("#demo-canvas");
const context = canvas.getContext("2d");

context.fillStyle = "#007F86";
context.fillRect(20, 20, 180, 70);
context.fillStyle = "#17365D";
context.font = "16px sans-serif";
context.fillText("Web Developer", 30, 115);
\end{lstlisting}
The canvas dimensions define its drawing surface. CSS can control how large it appears on the page, but changing only its displayed size may scale the drawing. For beginner projects, keep the example small and test it in the browser.

\section{Using JavaScript with Images}
JavaScript can respond to a button click by changing an image's source, updating alternative text, or adjusting presentation classes. Alternative text should continue to describe the image's purpose after a change. Images should have appropriate dimensions and should not be stretched in ways that distort their content.

\begin{lstlisting}[style=webcode,language=HTML]

     src="images/html-basics.jpg"
     alt="HTML code displayed in an editor">
<button id="change-image" type="button">

</button>
\end{lstlisting}

\begin{lstlisting}[style=webcode,language=JavaScript]

  image.src = "images/css-basics.jpg";

\chapter{Database Management Concepts}
A database becomes useful when information can be stored consistently, found quickly and updated without creating confusion. A school may need student records, a shop may maintain stock and sales, and a web application may keep account details and orders. A database management system (DBMS) provides the tools needed to organise this information and control how people and applications use it.

\photo{../Web developer-12th/images/computer-room.jpg}{Database infrastructure}{Figure 1.1. A computer room with server equipment illustrates infrastructure that supports database systems. Photograph: StellaAnnie, Wikimedia Commons, CC BY-SA 4.0.}
\section{Data, databases and DBMS}
Data is a recorded value such as a name, date, price or attendance status. A database is an organised collection of related data. A DBMS is software that creates, stores, retrieves and protects that data. MySQL is a widely used relational DBMS; other examples include PostgreSQL, Oracle Database and Microsoft SQL Server.

A database system supports more than storage. It can enforce rules, control access, manage simultaneous users, support backup and recovery, and help applications retrieve only the information they need. These controls reduce the risk of inconsistent or lost records.

\section{Tables, records, fields and keys}
In a relational database, a table stores one kind of entity. Rows represent records; columns represent attributes. A student table might contain student ID, name, class and date of admission. Each column has a data type, and each row should be identifiable in a reliable way.

A \keyterm{primary key} uniquely identifies each row and cannot be missing. A \keyterm{foreign key} links a row to a matching key in another table. A \keyterm{unique constraint} prevents duplicate values in a column or column group. A \keyterm{NOT NULL constraint} requires a value, while a \keyterm{CHECK constraint} can enforce a condition supported by the database engine.

\section{Relational and other database models}
Relational databases organise data in related tables and use SQL to work with it. NoSQL databases use other models, including document, key-value, column-family and graph structures. The appropriate model depends on the shape of the data, consistency needs, access patterns and operational requirements; no single model is best for every application.

\section{File systems and database systems}
A file system stores files and folders. It is appropriate for documents, images and many ordinary files. A DBMS adds structured queries, constraints, relationships and transaction handling that are valuable when many records must be managed together. File storage and databases often work side by side in one application.

\section{Normalisation and data quality}
Normalisation is a way of organising tables to reduce unnecessary repetition and update anomalies. For example, storing a department's address in every employee row means an address change must be repeated in many places. A separate department table allows employees to refer to one department record. Good normalisation begins with clear entities, keys and relationships; it should also reflect actual reporting and performance needs.

\section{Transactions and ACID}
A transaction groups operations that should succeed or fail as a unit. ACID summarises four important properties: Atomicity (all or nothing), Consistency (valid rules remain satisfied), Isolation (concurrent work is controlled), and Durability (committed changes persist according to the system's guarantees). Transactions matter in banking, ordering, stock control and any workflow where partial updates would create a misleading result.

\chapter{Structured Query Language and MySQL}
SQL is used to define database structures, retrieve records, change data and manage access. Although database products differ in some details, the basic ideas of tables, filtering, sorting, joins and constraints are widely shared.

\photo{../Web developer-12th/images/sql-programming.jpg}{SQL and programming code}{Figure 2.1. A code screen illustrates the syntax used to write and review database queries. Photograph: Lorenzo Cafaro, Wikimedia Commons, CC0 1.0.}
\section{Main categories of SQL commands}
\begin{itemize}
\item \textbf{DDL (Data Definition Language):} CREATE, ALTER and DROP define or change database objects.
\item \textbf{DML (Data Manipulation Language):} INSERT, UPDATE and DELETE change records.
\item \textbf{DQL (Data Query Language):} SELECT retrieves information; this label is often used for query statements.
\item \textbf{DCL (Data Control Language):} GRANT and REVOKE manage privileges.
\item \textbf{TCL (Transaction Control Language):} COMMIT and ROLLBACK manage transaction outcomes.
\end{itemize}

\section{Creating a database and table}
The following examples use MySQL-style syntax. Run them in a practice database, not against real records.

\begin{lstlisting}[style=webcode,language=SQL]
CREATE DATABASE training_centre;
USE training_centre;

CREATE TABLE students (
  student_id INT PRIMARY KEY,
  full_name VARCHAR(100) NOT NULL,
  course_name VARCHAR(80),
  marks DECIMAL(5,2) CHECK (marks >= 0 AND marks <= 100)
);
\end{lstlisting}
Choose data types that fit the values. INT is suitable for whole numbers; VARCHAR stores variable-length text; DATE stores a calendar date; DECIMAL is appropriate for exact decimal quantities such as money. Avoid storing every value as text when calculations, sorting or validation matter.

\section{Retrieving and filtering data}
SELECT names the columns to return. WHERE filters rows, ORDER BY sorts the result, and LIMIT can restrict the number of returned rows in MySQL.

\begin{lstlisting}[style=webcode,language=SQL]
SELECT student_id, full_name, marks
FROM students
WHERE marks >= 60
ORDER BY marks DESC
LIMIT 10;
\end{lstlisting}
Use explicit column names rather than relying on SELECT * in long-lived application queries. Explicit selections make the expected output easier to review and reduce accidental exposure when a table gains new columns.

\section{Adding, updating and deleting records}
\begin{lstlisting}[style=webcode,language=SQL]
INSERT INTO students (student_id, full_name, course_name, marks)
VALUES (101, 'Ananya Rao', 'Web Development', 86.50);

UPDATE students
SET marks = 88.00
WHERE student_id = 101;

DELETE FROM students
WHERE student_id = 101;
\end{lstlisting}
UPDATE and DELETE should be used with particular care. Before running a change, check the WHERE condition with a SELECT query and confirm that it identifies exactly the intended records. In real systems, use appropriate permissions, backups and transactions.

\section{Functions, grouping and aggregation}
SQL functions can transform values or summarise a set of records. String functions include UPPER, LOWER, CONCAT and LENGTH; numeric functions include ROUND, CEIL, FLOOR and ABS; date functions depend on the DBMS. Aggregate functions such as COUNT, SUM, AVG, MIN and MAX calculate a summary across rows.

\begin{lstlisting}[style=webcode,language=SQL]
SELECT course_name,
       COUNT(*) AS learner_count,
       ROUND(AVG(marks), 2) AS average_marks
FROM students
GROUP BY course_name
ORDER BY average_marks DESC;
\end{lstlisting}
GROUP BY creates groups for aggregation. HAVING filters groups after aggregation, while WHERE filters rows before grouping. NULL values require care: most aggregate functions ignore NULL inputs, and comparisons with NULL use IS NULL or IS NOT NULL rather than ordinary equality.

\section{Joins and relationships}
A JOIN combines rows from related tables. An INNER JOIN returns matching rows. A LEFT JOIN retains every row from the left table and includes matching data from the right where available. Joins are easier to reason about when key columns are named clearly and their relationships are documented.

\begin{lstlisting}[style=webcode,language=SQL]
SELECT s.full_name, c.course_title
FROM students AS s
INNER JOIN courses AS c
  ON s.course_id = c.course_id;
\end{lstlisting}

\section{Installation and safe database practice}
For learning, use the official MySQL Community Edition download and follow current installation instructions for your operating system. A typical setup may include MySQL Server and a client such as MySQL Workbench. Create a dedicated practice account, use a strong password, keep the server local while learning, and do not expose the database port to the public internet without a carefully designed security plan.

\chapter{SQL Functions and Data Handling}
Functions help queries express common calculations without requiring every operation to be performed manually outside the database. A function accepts a value or expression and returns a result. Exact names and behaviour can differ across database products, so check the documentation for the system in use.

\section{String functions}
UPPER and LOWER change letter case, CONCAT joins text, LENGTH reports the length according to the DBMS's rules, and TRIM removes surrounding whitespace. SUBSTRING returns part of a string. These operations are useful for formatting output, preparing search values and producing reports. They should not be used as a substitute for storing clean, well-validated data.

\begin{lstlisting}[style=webcode,language=SQL]
SELECT UPPER(full_name) AS display_name,
       LENGTH(full_name) AS name_length
FROM students;
\end{lstlisting}

\section{Numeric functions}
ABS returns a non-negative magnitude, ROUND rounds a number to a specified precision, and CEIL/FLOOR round upward/downward to integer boundaries. Check the effect of rounding before using it in financial or assessment calculations; the displayed value and stored value are not always the same.

\section{Date and time functions}
Date functions can extract parts of a date, compare dates, format a value or calculate intervals. MySQL provides functions such as CURDATE(), NOW(), YEAR() and \texttt{DATE\_FORMAT()}. Other SQL systems may use different names or arguments. Store dates using date/time types when possible, rather than ambiguous strings such as 03/04/25.

\section{Aggregate functions and NULL values}
COUNT counts rows or non-NULL values depending on its argument; SUM totals numeric values; AVG computes a mean; MIN and MAX return the smallest and largest values. NULL means that a value is unknown or absent, not zero and not an empty string. Queries should handle missing values intentionally.

\begin{lstlisting}[style=webcode,language=SQL]
SELECT COUNT(*) AS total_records,
       COUNT(marks) AS records_with_marks,
       AVG(marks) AS mean_marks,
       MIN(marks) AS lowest_marks,
       MAX(marks) AS highest_marks
FROM students;
\end{lstlisting}

\section{Permissions and transactions}
GRANT assigns permitted actions to a database account; REVOKE removes permissions. Follow least privilege: give each account only the access it needs. COMMIT confirms a transaction and ROLLBACK abandons uncommitted changes. Transaction support and behaviour depend on the storage engine and the operations being performed.

Use a supported PHP installation or a local development bundle, and follow the current official installation instructions. Save the following as \texttt{hello.php} in the configured project directory and open it through the local development server.

PHP variables begin with a dollar sign. Statements commonly end with a semicolon. The \texttt{echo} construct outputs content. When displaying user-controlled text inside HTML, escape it for the correct output context; escaping is a security control, not just a formatting choice.

\section{Variables, types and operators}
Variables hold values such as strings, integers, floating-point numbers, booleans, arrays and objects. PHP is dynamically typed, but developers should still validate input and make assumptions clear. Arithmetic operators calculate values; comparison operators compare values; logical operators combine conditions. Use strict comparisons where appropriate and avoid depending on surprising type conversions.

\section{Conditions and loops}
\begin{lstlisting}[style=webcode,language=PHP]
$marks = 74;
if ($marks >= 80) {
    echo "Excellent";
} elseif ($marks >= 50) {
    echo "Pass";
} else {
    echo "Needs more practice";
}
\end{lstlisting}
Conditions allow code to choose between actions. Loops repeat work while a condition holds or for each item in a collection. Every loop needs a sensible stopping condition so that it does not run forever.

\section{Forms and request data}
HTML forms commonly submit data with GET or POST. GET data is typically included in the URL and is suitable for retrieval requests; POST sends data in the request body and is often used for changes. POST does not automatically make data private or safe: use HTTPS, validation, access control and appropriate request protections.

\begin{lstlisting}[style=webcode,language=PHP]
<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $name = trim($_POST['name'] ?? '');
    if ($name === '') {
        echo "Please enter a name.";
    } else {
        echo "Received a valid name.";
    }
}
?>
\end{lstlisting}
The example demonstrates basic checking only. A real form should include a suitable HTML form, a clear label, server-side validation, CSRF protection where relevant, safe output encoding and meaningful error handling.

\chapter{PHP Arrays, Strings and Functions}
\section{Arrays}
An array stores several values under one variable. An indexed array uses numeric keys, an associative array uses named keys, and a multidimensional array contains arrays inside another array. Select the structure that best represents the data.

\begin{lstlisting}[style=webcode,language=PHP]
$courses = ["HTML", "CSS", "JavaScript"];
$learner = [
    "name" => "Ananya",
    "course" => "Web Development",
    "completed" => true
];

foreach ($courses as $course) {
    echo htmlspecialchars($course, ENT_QUOTES, 'UTF-8') . "<br>";
}
\end{lstlisting}
Array functions can sort values, count elements, test for keys and transform data. Be mindful that some sorting functions reindex numeric keys, while others preserve key associations. Check the function's documented behaviour before depending on the original order.

\section{Working with strings}
String operations can trim extra spaces, change letter case, find a substring, split text or join pieces. When processing input, consider empty strings, unexpected encodings and very long values. A value should be checked according to its intended meaning, not merely accepted because it is a string.

\section{Functions and parameters}
A function gives a name to a reusable task. Parameters receive input, and a return value communicates a result. Small functions are easier to test, reuse and maintain than long blocks that mix unrelated responsibilities.

\begin{lstlisting}[style=webcode,language=PHP]
function calculateAverage(array $scores): ?float {
    if (count($scores) === 0) {
        return null;
    }
    return array_sum($scores) / count($scores);
}

$average = calculateAverage([70, 80, 90]);
\end{lstlisting}
PHP passes values by value by default; a parameter can be explicitly passed by reference using an ampersand in its declaration. References should be used only when changing the caller's variable is part of the function's intended behaviour. Recursive functions call themselves and must have a base case to stop the recursion.

\section{Server variables and HTTP headers}
The \texttt{\$\_SERVER} superglobal provides request and server information, such as the request method and script path. Values should not be blindly trusted as proof of identity or permission. HTTP headers communicate metadata and response instructions. Header operations must be sent before body output, and redirects should be followed by an exit where appropriate.

\section{Error handling and maintainability}
Use clear names, consistent formatting, comments that explain intent, and functions with a focused purpose. During development, errors can be logged for diagnosis. Production systems should avoid showing stack traces, secrets or internal paths to visitors. Logs should not unnecessarily contain passwords, session tokens or sensitive personal information.

\chapter{PHP and MySQL Database Applications}
A web application often needs to save and retrieve information. PHP can connect to MySQL, send queries and use the returned rows to generate a response. The connection, query and output stages all need careful error handling and security controls.

\photo{../Web developer-12th/images/server-rack.jpg}{Application and server infrastructure}{Figure 6.1. Web applications depend on server systems to process requests and access stored data. Photograph: Ricardo Moctezuma López / ronK, Wikimedia Commons, CC BY-SA 2.5.}
\section{Connection choices}
Modern PHP applications commonly use PDO or MySQLi. Both support prepared statements. PDO offers a consistent interface across supported database drivers; MySQLi is designed for MySQL-compatible databases. Use the interface supported by the project and keep credentials outside public source files, for example in environment configuration that is not committed to a repository.

\section{Prepared statements}
Never build a query by joining untrusted input directly into SQL text. Prepared statements separate the query structure from the supplied values and help prevent SQL injection.

\begin{lstlisting}[style=webcode,language=PHP]
<?php
$pdo = new PDO(
    'mysql:host=127.0.0.1;dbname=training_centre;charset=utf8mb4',
    getenv('DB_USER'),
    getenv('DB_PASSWORD'),
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
);

$stmt = $pdo->prepare(
    'SELECT student_id, full_name FROM students WHERE student_id = :id'
);
$stmt->execute(['id' => $studentId]);
$student = $stmt->fetch(PDO::FETCH_ASSOC);
?>
\end{lstlisting}
This is a learning pattern, not a complete production configuration. The variable \texttt{\$studentId} must be validated, the credentials must be configured securely, and exceptions should be handled by the application without exposing sensitive details to the browser.

\section{Create, read, update and delete}
CRUD describes four common data operations: create a record, read records, update existing information and delete records. Each operation should verify that the user is authorised to perform it. Deleting records may require confirmation, audit logging or a retention process depending on the system's requirements.

\section{SQL injection}
SQL injection occurs when untrusted input is interpreted as part of a query's executable SQL syntax. It may expose data, bypass checks or modify records. Prepared statements are the primary defence for values; least-privilege database accounts, validation, safe error handling and security testing add further protection. Escaping alone is not a substitute for prepared statements.

\section{Output encoding and sessions}
When displaying text in HTML, use context-appropriate output encoding, such as \texttt{htmlspecialchars} for ordinary HTML text. Authentication systems should use secure session settings, regenerate session identifiers after login, enforce permissions on the server and protect sensitive actions. Hiding a button in the browser is not authorisation.

\section{A responsible development checklist}
\begin{itemize}
\item Use a separate database account with only the privileges needed.
\item Store credentials in environment variables or a protected configuration system.
\item Use prepared statements for values in SQL queries.
\item Validate input on the server and encode output for its context.
\item Use HTTPS for real deployments and protect sessions.
\item Log useful security events without recording secrets.
\item Back up data and test recovery procedures.
\end{itemize}

\chapter{Productivity, Quality and Professional Work Habits}
Productivity is not simply completing a large number of tasks. Good work is accurate, useful and delivered with appropriate use of time and resources. In a software workplace, productivity improves when requirements are understood, tasks are prioritised, tools are maintained, communication is clear and defects are found early.

\section{Planning and prioritising}
Break large assignments into smaller tasks with clear outcomes. Estimate the effort, identify dependencies and reserve time for review. A simple task board can show work that is planned, in progress, waiting for review and complete. When priorities change, communicate the impact rather than silently missing a deadline.

\section{Quality and continuous improvement}
Quality means meeting agreed requirements reliably. Use checklists, peer review, testing and documented procedures. When an error occurs, look for the cause and improve the process instead of focusing only on blame. Useful measures might include defects found after release, rework, task completion and customer feedback; a single metric rarely tells the whole story.

\section{Communication and teamwork}

\section{Managing digital work responsibly}
Organise files with meaningful names, keep versions under control, back up important work and avoid saving confidential material in unapproved locations. Lock the screen when stepping away, use strong authentication and report suspicious messages or unexpected access requests.

\chapter{Health and Safety Procedures in the Workplace}
A safe workplace is created through planning, training, suitable equipment and shared responsibility. Hazards may be physical, electrical, ergonomic, chemical, environmental or psychosocial. Identifying a hazard early gives people a chance to remove it or reduce the risk before someone is harmed.

\photo{../Web developer-12th/images/ergonomic-workstation.png}{Ergonomic computer workstation}{Figure 8.1. An ergonomic workstation supports comfortable computer use and reduces avoidable strain. Illustration: Marcel Kollmar and Partynia, Wikimedia Commons, CC BY-SA.}
\section{Hazard and risk}
A hazard is something that can cause harm. Risk considers how likely that harm is and how serious it could be. A loose cable across a walkway is a hazard; the risk increases when people regularly walk through the area and could trip. Report hazards promptly and follow the organisation's safety procedure.

\section{Hierarchy of controls}
Where possible, remove the hazard first. If elimination is not practical, consider substituting a safer option, using engineering controls, improving administrative procedures and using personal protective equipment where required. PPE is important but should not be the only control when more effective options are available.

Adjust the chair, desk and screen so the body can remain in a comfortable, neutral position. Keep frequently used items within easy reach, avoid glare and take regular short movement breaks. Repeated discomfort, headaches or eye strain should be reported and addressed rather than treated as an unavoidable part of computer work.

\section{Electrical safety and emergency response}
Do not use damaged plugs, exposed wires or overloaded extension boards. Keep liquids away from electrical equipment and never attempt repairs beyond your training or authorisation. Know emergency exits, alarms, first-aid arrangements and reporting contacts. In an emergency, follow local procedures and contact trained responders; do not put yourself at risk by attempting an unfamiliar rescue.

\section{Incident reporting}
Report injuries, near misses, unsafe conditions and equipment faults according to workplace policy. Record factual details such as location, time, what was observed and immediate controls taken. Timely reporting helps prevent recurrence and supports a safer environment for everyone.

\chapter{Waste Management, Recycling and Resource Conservation}
Workplaces use electricity, water, paper, equipment and other materials. Waste prevention and careful resource use reduce environmental impact and can also lower operating costs. Sustainability works best when it is part of routine purchasing, maintenance and daily decisions.

\section{Identify and separate waste}
Waste should be separated according to local rules and the organisation's procedures. Common categories include recyclable paper and cardboard, metals, glass, suitable plastics, organic waste and residual waste. Batteries, electronic equipment, lamps and other special waste may need dedicated collection because they can contain hazardous materials.

\section{The waste hierarchy}
The preferred order is to prevent waste first, reduce unnecessary use, reuse suitable items, recycle correctly and dispose of residual waste safely. Recycling is valuable, but avoiding unnecessary consumption usually prevents more waste from being created in the first place.

Computers, cables, printers, batteries and other electronic items should not be placed in ordinary waste when local rules require special handling. \section{Conserving energy and water}

\chapter{Diversity, Equality and Inclusive Workplaces}
An inclusive workplace makes it possible for people with different backgrounds, experiences and abilities to participate and contribute. Respect is shown through fair procedures, accessible communication, equitable opportunities and prompt action when discrimination or harassment occurs.

\section{Diversity and equality}
Diversity describes differences among people, including experience, culture, language, age, gender, disability and perspective. Equality means people are treated fairly and have equal rights and opportunities. Equity recognises that removing barriers may require different forms of support so people can participate meaningfully.

\section{Everyday inclusive behaviour}
Use respectful language, listen without interruption, avoid assumptions about a person's abilities or background, and give credit fairly. Meetings should make room for different voices. Work assignments, training, performance assessment and promotion should follow transparent and relevant criteria.

\section{Discrimination and harassment}
Discrimination involves unfair treatment linked to a protected or personal characteristic, according to applicable law and policy. Harassment can include unwelcome conduct that intimidates, humiliates or creates a hostile environment. Follow organisational reporting channels and relevant law. Bystanders should not escalate a situation; they can support the affected person and report concerns safely.

\section{Gender equality and work-life responsibilities}
Fair workplaces apply consistent standards, provide equal access to learning and advancement, and address barriers that prevent people from participating. Family responsibilities, caregiving and safety concerns should be handled through applicable policies and law rather than stereotypes about who should perform particular roles.

\section{Building an inclusive team}
Use clear selection criteria, accessible training material, fair performance feedback and a reliable process for raising concerns. Review workplace practices regularly. Inclusion is not achieved by a slogan; it requires people to notice barriers and improve the way work is organised.

\chapter{Accessibility and Policies for Persons with Disabilities}
Accessibility means that people can use facilities, information, services and digital tools as independently as possible. A barrier may be physical, communicative, procedural or digital. Inclusive practice identifies barriers and makes reasonable adjustments in line with applicable law and workplace policy.

\photo{../Web developer-12th/images/wheelchair-access.jpg}{Accessible workplace}{Figure 11.1. An accessible workplace considers clear space and practical access around desks. Photograph: David290, Wikimedia Commons, CC BY-SA 4.0.}
\section{Recognising different access needs}
People may have mobility, vision, hearing, learning, communication or other access requirements. Do not assume that everyone with the same disability needs the same support. Ask respectfully what adjustment is useful, protect privacy and involve the person in decisions that affect their work.

\section{Digital accessibility}
For websites and learning resources, use meaningful headings, descriptive link text, form labels, sufficient colour contrast, keyboard-accessible controls and alternative text for informative images. Do not communicate important information through colour alone. Captions and transcripts can help people who cannot hear audio; text alternatives can help people who cannot access a visual diagram.

\section{Physical and workplace adjustments}
Possible adjustments include accessible routes, suitable desk arrangements, assistive technology, flexible communication formats, adjusted work processes and accessible emergency information. The correct adjustment depends on the person, role, environment and applicable requirements. Keep routes clear and ensure emergency plans include people who may need assistance.

\section{Respectful support and privacy}
Speak directly to the person rather than only to a companion. Ask before offering physical assistance or moving mobility equipment. Do not disclose a person's disability or medical information without an appropriate basis. Apply workplace policies and relevant Indian law, including the Rights of Persons with Disabilities Act, 2016, where applicable; consult official guidance for current obligations.

\chapter{Introduction to Artificial Intelligence}
\section{What is artificial intelligence?}
Artificial Intelligence (AI) is a field of computing concerned with building systems that perform tasks commonly associated with human intelligence. These tasks may include recognising patterns, understanding language, interpreting images, making predictions and selecting actions. An AI system does not have to think exactly like a person; it is designed to perform a particular task using data, rules or learned patterns.

The word \keyterm{artificial} means made by people, while \keyterm{intelligence} includes abilities such as learning, reasoning, understanding information and solving problems. A spam filter, a voice assistant, a translation service and a system that recognises objects in photographs are everyday examples of AI-supported applications.

\section{Core abilities associated with AI}
\begin{itemize}

\item \keyterm{Reasoning:} applying rules or relationships to reach a conclusion.
\item \keyterm{Problem solving:} considering possible steps and selecting a suitable solution.
\item \keyterm{Perception:} interpreting images, sound or other signals from the environment.
\item \keyterm{Language processing:} working with written or spoken human language.
\end{itemize}
Not every AI application uses all these abilities. A simple rule-based system may follow conditions written by a developer, while a machine-learning system may learn useful patterns from examples.

\section{AI in everyday life}
AI-supported features can appear in email spam detection, maps and route suggestions, speech recognition, translation, accessibility tools, shopping recommendations, fraud alerts and image search. \section{Types of Artificial Intelligence}
AI can be grouped in more than one way. One common classroom explanation groups it by the range of tasks it could perform. Another describes how a system behaves or uses information. These are useful learning frameworks, not proof that every category already exists as a real product.

\subsection{Types based on capability}
\begin{itemize}

\item \keyterm{Artificial General Intelligence (AGI):} a proposed system that could learn and perform a broad range of intellectual tasks at a flexible, human-like level. It has not been established as a generally available system.
\item \keyterm{Artificial Superintelligence (ASI):} a hypothetical concept describing AI that would exceed human abilities across many important areas. It is an idea discussed in research and public debate, not an established current technology.
\end{itemize}

\chapter{Programming Basics and Algorithms}
\section{What is programming?}
Programming is the process of writing instructions that a computer can execute. A program translates a solution into steps that are precise enough for a computer to follow. Programming is used to create websites, games, mobile applications, data tools and AI systems.

\section{Algorithms and logical steps}
An \keyterm{algorithm} is a finite, ordered set of steps for solving a problem. \chapter{Data Pre-processing}
\section{Why data need preparation}
Collected data are often inconsistent or incomplete. Data pre-processing is the set of steps used to inspect and prepare data before analysis or machine learning. Poor-quality input can lead to misleading summaries and unreliable model predictions. Preparation should be appropriate to the question being studied.

\section{Common data-quality issues}
Missing values occur when a field has not been recorded. Duplicates represent repeated records. Inconsistent formats may use different spellings, date patterns or units. \section{A careful cleaning process}

\item Inspect column names, data types, units and sample records.

\item Validate the cleaned data and compare it with the original.

\chapter{Python Programming}
\section{Control structures in Python}
A Python program normally executes statements in the order in which they appear. Control structures let a program choose between alternatives or repeat a set of instructions. These structures are important when a solution must respond to different inputs rather than follow one fixed path.

\subsection{Selection with \texttt{if}, \texttt{if...else} and \texttt{if...elif...else}}
An \texttt{if} statement tests a condition. If the condition is true, its indented block runs. An \texttt{if...else} statement provides an alternative when the condition is false. An \texttt{if...elif...else} ladder checks several conditions in sequence; the first true branch is executed.

\begin{lstlisting}[style=pythonstyle]
marks = int(input("Enter marks: "))
if marks >= 80:
    print("Grade A")
elif marks >= 60:
    print("Grade B")
elif marks >= 40:
    print("Grade C")
else:
    print("Needs improvement")
\end{lstlisting}
Indentation is part of Python syntax. Statements belonging to a branch must be indented consistently. Conditions can use comparison operators such as \texttt{==}, \texttt{!=}, \texttt{>}, \texttt{<}, \texttt{>=} and \texttt{<=}, along with logical operators \texttt{and}, \texttt{or} and \texttt{not}.

\subsection{Repetition using loops}
A \texttt{for} loop iterates over items in a sequence or over values produced by \texttt{range()}. A \texttt{while} loop repeats while its condition remains true. Every loop should make progress toward termination; otherwise, a \texttt{while} loop can continue indefinitely.

\begin{lstlisting}[style=pythonstyle]
total = 0
for number in range(1, 6):
    total += number
print("Total:", total)
\end{lstlisting}
The program adds the integers from 1 through 5. The \texttt{range(1, 6)} expression stops before 6, so the values are 1, 2, 3, 4 and 5. A nested loop is a loop placed inside another loop and is useful for tables, patterns and two-dimensional data.

\subsection{Loop control and common errors}
The \texttt{break} statement stops the nearest loop, while \texttt{continue} skips the remaining statements in the current iteration and moves to the next one. These statements should be used only when they make the program easier to follow. A common error is an off-by-one mistake, in which a loop repeats one time too many or too few. Carefully check the starting value, stopping condition and update step.

\begin{lstlisting}[style=pythonstyle]
for number in range(1, 8):
    if number == 5:
        continue
    print(number)
\end{lstlisting}
This example prints 1, 2, 3, 4, 6 and 7. The value 5 is skipped, but the loop continues. Testing a loop with a small set of known values is a useful way to confirm that it behaves as intended.

When a program receives data from a user, it should also consider invalid input. For example, converting a word to an integer with \texttt{int()} raises an error. A more robust program can validate input or handle a conversion error instead of terminating unexpectedly.

\section{Functions in Python}
A function is a named, reusable block of code that performs a task. Functions help divide a larger problem into smaller parts, reduce repetition and make a program easier to test. Python includes built-in functions such as \texttt{print()}, \texttt{len()} and \texttt{sum()}; programmers can also define their own functions with \texttt{def}.

\begin{lstlisting}[style=pythonstyle]
def mean(values):
    if len(values) == 0:
        return None
    return sum(values) / len(values)

marks = [72, 81, 67, 90]
print(mean(marks))
\end{lstlisting}
The function accepts a list as an argument and returns its arithmetic mean. The \texttt{return} statement sends a result back to the calling code. Parameters are names in a function definition; arguments are the values supplied when it is called. A local variable created inside a function is normally available only within that function.

\subsection{Parameters, return values and scope}
Functions may accept zero or more parameters. A function that returns a value can be used in an expression, while a function that only performs an action may return \texttt{None}. Variables defined inside a function have local scope. Clear names, short functions and appropriate validation improve readability and reliability.

\subsection{Designing a useful function}
A well-designed function usually has one clear responsibility. Its name should describe the task, its parameters should represent the information needed, and its return value should be predictable. Repeating the same calculation in several places makes later changes harder; placing that calculation in one function helps keep results consistent.

\begin{lstlisting}[style=pythonstyle]
def percentage(score, maximum):
    if maximum <= 0:
        raise ValueError("Maximum must be positive")
    return (score / maximum) * 100

print(percentage(45, 50))
\end{lstlisting}
The function checks that the maximum possible score is positive before performing the calculation. This is an example of input validation. In larger programs, functions can be tested with normal values, boundary values and invalid values. A function should also be documented when its purpose or expected inputs are not obvious.

\subsection{Tracing a program step by step}
Tracing means following a program's statements in the order in which they execute and recording how important variables change. It is useful when the output differs from what was expected. Start with the initial values, follow each condition, and update variables only when the relevant statement executes. A small trace table written in a notebook can help beginners reason about loops without relying on guesswork.

Consider a counter that begins at zero and increases once for each item processed. If the update statement is accidentally placed outside the loop, the counter may not represent the number of items. Similarly, changing the order of statements can change the result. Reading the code line by line and testing a small example makes such mistakes easier to identify.

\subsection{Writing readable and maintainable code}
Readable code uses meaningful names, consistent indentation and short blocks that have a clear purpose. A name such as \texttt{total\_marks} communicates more than a single-letter name such as \texttt{x}. Comments should explain the reason for a decision or a non-obvious step rather than repeat every line in English. Blank lines can separate logical parts of a program, but excessive spacing makes a short program harder to follow.

A normal test checks an expected everyday input. A boundary test checks a value near a limit, such as marks equal to the minimum passing score. Testing all three kinds of input can reveal problems that one successful example would not show.

For example, a percentage function should be tested with a score of zero, a score equal to the maximum, and a maximum value of zero. The last case should be rejected because division by zero is undefined. Testing does not prove that a program has no defects, but it provides evidence that the program behaves as expected for the cases considered.

\chapter{Data Science with NumPy}
\section{Introduction to NumPy}
NumPy is a Python library for numerical computing. Its central data structure is the multidimensional array, commonly called an \texttt{ndarray}. Compared with ordinary Python lists, NumPy arrays support convenient element-wise operations and efficient numerical processing. NumPy is widely used as a foundation for scientific computing and data analysis.

\begin{lstlisting}[style=pythonstyle]
import numpy as np
marks = np.array([72, 81, 67, 90])
print(marks.mean())
print(marks.max())
print(marks.min())
\end{lstlisting}
The import statement makes NumPy available under the short name \texttt{np}, a common convention. The array stores four numerical values. Its methods calculate the mean, maximum and minimum without requiring a manually written loop.

\subsection{Array properties}
The \texttt{ndim} attribute reports the number of dimensions, \texttt{shape} reports the size along each dimension, \texttt{size} gives the total number of elements, and \texttt{dtype} indicates the element data type. A one-dimensional array can represent a sequence; a two-dimensional array can represent rows and columns.

table = np.array([[10, 20, 30],
                  [40, 50, 60]])

print(table.shape)  # (2, 3)
print(table.size)   # 6
\end{lstlisting}

\section{Array manipulation}
Arrays can be reshaped, joined, split, indexed and sliced. A reshape operation changes the arrangement of elements without changing their total number. Indexing selects particular elements; slicing selects a range. The requested shape must be compatible with the number of values in the array.

\begin{lstlisting}[style=pythonstyle]
values = np.array([1, 2, 3, 4, 5, 6])
matrix = values.reshape(2, 3)
print(matrix)
print(matrix[:, 1])
\end{lstlisting}
The expression \texttt{matrix[:, 1]} selects the second column. In a slice, a colon represents a range along an axis. Understanding array shape is essential when combining data from multiple sources.

\subsection{Indexing and slicing}
NumPy uses zero-based indexing, which means the first element has index 0. Negative indices count from the end of an array. Slicing selects a range using the form \texttt{start:stop:step}; the stop position is excluded. For a two-dimensional array, separate index expressions identify the row and column.

\begin{lstlisting}[style=pythonstyle]
scores = np.array([55, 68, 72, 89, 94])
print(scores[0])       # first value
print(scores[-1])      # last value
print(scores[1:4])     # values at positions 1, 2, 3
print(scores[scores >= 70])
\end{lstlisting}
The last line uses a Boolean condition to select values that are at least 70. Such filtering is useful when exploring measurements, marks or other numerical records. The original data should be preserved when an analysis requires a record of the unmodified values.

\subsection{Broadcasting and practical cautions}
Broadcasting allows NumPy to combine arrays of compatible shapes. For example, adding a single number to an array adds that number to every element. More complex broadcasting follows shape rules, so dimensions should be checked when an operation produces an unexpected result. Arrays should also use appropriate numeric types: converting a decimal measurement to an integer can discard its fractional part.

\subsection{Joining, splitting and copying}
Functions such as \texttt{np.concatenate()} join arrays along a compatible axis. Splitting functions divide arrays into smaller arrays. A view can share underlying data with another array, whereas \texttt{copy()} creates independent data. Changing a shared view may therefore affect the original array.

\section{Array computation}
NumPy supports arithmetic, comparison, logical, statistical and mathematical operations. Many operations are performed element by element. Broadcasting allows arrays with compatible shapes to participate in an operation without manually copying values.

\begin{lstlisting}[style=pythonstyle]
a = np.array([1, 2, 3])
print(a * 2)       # [2 4 6]
print(a + 10)      # [11 12 13]
print(np.sqrt(a))  # square roots
\end{lstlisting}
Common statistical functions include \texttt{sum()}, \texttt{mean()}, \texttt{median()}, \texttt{min()} and \texttt{max()}. Mathematical utilities include trigonometric functions and conversions between degrees and radians. The result type depends on the operation and input types.

\subsection{Why vectorised operations are useful}
A vectorised operation expresses a calculation for an entire array instead of describing each element with a Python loop. This often makes numerical code shorter and can improve performance. The expression should still be chosen for clarity: a compact calculation is not helpful if its meaning is difficult to understand.

For example, if a set of temperatures is stored in an array in degrees Celsius, the conversion to Fahrenheit can be applied to every value using \texttt{temperatures * 9 / 5 + 32}. The formula is applied element by element. Before interpreting a result, check the units, the range of values and whether any missing or unusual measurements need attention.

The structure should reflect the meaning of the data, not merely the shape that is convenient to type.

\subsection{Missing values and unusual measurements}
A numerical array can contain values that are mathematically valid but incorrect for the real problem. For instance, a temperature of 900 degrees may be a valid number in a computer but an implausible reading for a classroom thermometer. A negative mark may be outside the permitted range for an examination. Range checks and knowledge of the measurement context help identify such cases.

Missing values require a deliberate decision. If a sensor did not record a reading, replacing it with zero may falsely imply that the measured quantity was zero. Depending on the purpose, the missing value may be excluded from a calculation, investigated, or replaced using a justified method. Always record the choice and consider how it could affect the conclusion.

\subsection{Efficiency and memory}
NumPy is designed for numerical work with arrays and often performs large element-wise calculations more efficiently than manually looping through ordinary Python lists. The actual performance depends on the size of the data, the operation and the computer. For a tiny list, readability matters more than trying to optimise every operation. For large datasets, choosing an appropriate data type and avoiding unnecessary copies can reduce memory use.

import pandas as pd

A DataFrame can contain columns of different data types. Column labels help identify fields, while the row index identifies records. Data should be checked for missing values, duplicate records and inconsistent formats before analysis.

\section{Working with Series and DataFrames}
A Series stores values with associated labels. A DataFrame groups multiple columns into a table. Pandas can create a Series from a list or dictionary, select columns, filter rows, sort values and calculate summaries.

\begin{lstlisting}[style=pythonstyle]
marks = pd.Series([72, 88, 64, 95])
print(marks.mean())
print(marks[marks >= 80])
\end{lstlisting}
Boolean filtering produces the values that satisfy a condition. In a DataFrame, a similar condition can be used to select records. Labels and positions should not be confused: label-based selection and integer-position selection have different purposes.

\subsection{Selecting, sorting and grouping records}
Pandas makes it possible to select a subset of rows using a condition, sort records by a column and calculate summaries for groups. These operations help turn a large table into information that answers a particular question. A filter should be linked to a clear question, such as identifying records above a chosen threshold.

\begin{lstlisting}[style=pythonstyle]
high_scores = students[students["Marks"] >= 80]
sorted_students = students.sort_values("Marks", ascending=False)
print(high_scores)
print(sorted_students)
\end{lstlisting}
The first expression selects students whose marks are at least 80; the second orders the records from highest marks to lowest. In real projects, the meaning of each column and the unit of measurement should be recorded so that the output is interpreted correctly.

\subsection{Cleaning and summarising data}
Data cleaning may include handling missing values, correcting data types, removing duplicates and standardising text. The correct treatment depends on what a missing or unusual value means in the real context. Deleting records without review can distort the analysis.

A missing value can mean that information was not collected, was not applicable or was accidentally omitted. These situations do not always have the same meaning. Depending on the task, a missing value may be left as missing, investigated with the data owner, or handled using a documented method. Replacing all missing values with zero is not always appropriate because zero may be a valid measurement.

Duplicate records also need careful review. Some duplicates are accidental copies, while others represent legitimate repeated events. Before removing them, check which fields define a unique record. Cleaning decisions should be documented so that another person can understand how the original data was transformed.

\begin{lstlisting}[style=pythonstyle]
print(students.head())
print(students.info())
print(students.isna().sum())
print(students.describe())
\end{lstlisting}
The \texttt{head()} method previews records, \texttt{info()} summarises columns and data types, \texttt{isna().sum()} counts missing values by column, and \texttt{describe()} gives descriptive statistics for suitable columns.

\section{Data visualisation using Matplotlib}
Data visualisation presents information graphically so that patterns, comparisons and changes can be understood. Matplotlib is a Python library for creating charts. A bar chart is suitable for comparing a small number of categories. A line chart is often appropriate for a measurement recorded over time, such as monthly rainfall. A scatter plot can help reveal whether two numerical variables appear to be related. A histogram shows the distribution of a numerical variable by grouping values into intervals. No chart proves a cause-and-effect relationship by itself.

A chart should include a title that states what is being shown, labels that explain the axes, and units where relevant. The scale should not exaggerate small differences. A Pandas Series is a one-dimensional labelled structure. A DataFrame combines rows and columns and can contain columns with different data types. The index labels rows, while column names identify fields. An index is not necessarily a unique identity for a real-world person or item; if a reliable identifier is required, it should be designed and checked separately.

\subsection{Filtering records carefully}
Filtering selects records that satisfy a condition. Multiple conditions can be combined, but each condition should be enclosed in parentheses when using Pandas Boolean expressions. When group sizes differ, a total and an average answer different questions; choose the statistic that fits the purpose.

These checks reduce the risk of silently removing valid records or introducing errors.

An Artificial Neural Network (ANN) is a computational model inspired in a broad way by networks of connected neurons. In a typical neural network, units receive numerical inputs, apply weights and a bias, pass the result through an activation function, and send outputs to the next layer. Networks can learn patterns by adjusting parameters during training.

\subsection{Training and prediction}
During training, a network processes examples and compares its output with the expected target. A loss function measures the difference, and an optimisation method adjusts model parameters to reduce that loss. After training, the model can make predictions on new inputs. Performance on training examples alone is not enough; evaluation on separate data helps estimate how well the model generalises.

\subsection{Weights, activation functions and loss}
A weight controls how strongly an input contributes to a unit's calculation. A bias shifts the calculation, and an activation function transforms the result. Common activation functions include ReLU for many hidden layers and sigmoid for some binary-output tasks. The choice depends on the model design and the problem being solved.

A loss function measures how far a model's predictions are from the expected targets during training. The training process adjusts weights and biases to reduce the loss. A lower training loss does not automatically mean that a model will perform well on unfamiliar examples, so evaluation must use data that was not used to fit the model.

\subsection{Overfitting and generalisation}
Overfitting occurs when a model learns details or noise specific to its training examples and performs poorly on new data. A model that is too simple may also fail to capture useful patterns; this is often described as underfitting. Careful data splitting, suitable model complexity and evaluation on representative examples help assess generalisation. The test set should not be repeatedly used to tune every decision, because that can make the final estimate overly optimistic.

\section{Applications of neural networks}
Neural networks are used in image and speech recognition, handwriting recognition, language processing, recommendation systems, forecasting and selected healthcare applications. Face recognition can support device authentication; speech-to-text systems convert spoken language into text; recommendation systems rank items that may interest a user. Such applications can make errors, so human review and suitable safeguards remain important, especially in high-impact settings.

\subsection{Responsible use}
Data quality, privacy, fairness and transparency affect the reliability of an AI application. A model trained on unrepresentative examples may perform poorly for some groups. Sensitive personal data should be handled carefully, and a prediction should not automatically be treated as a fact. The system's purpose, limitations and evaluation results should be documented.

\subsection{Privacy, fairness and human oversight}
Responsible AI development begins with asking whether the data is needed and whether it may be used for the intended purpose. Personal details should not be collected simply because they are available. Access should be limited, files should be protected, and information should not be shared without appropriate permission.

Fairness requires checking whether the examples represent the people and situations in which the system will be used. An error can affect groups differently, especially when the training data is incomplete or unbalanced. A responsible project explains known limitations and provides a way for a person to review important decisions. AI outputs should be treated as information to assess, not as unquestionable truth.

Python's data-science ecosystem includes tools for different stages of an AI workflow. NumPy supports numerical arrays; Pandas supports tabular data handling; Matplotlib supports visualisation; Scikit-learn provides common machine-learning algorithms and evaluation utilities; TensorFlow and Keras support the development of neural-network models; XGBoost provides optimised gradient-boosting methods.

A neural network transforms input values through a series of connected calculations. In a simple unit, inputs are multiplied by weights, combined with a bias and passed through an activation function. The output of one layer becomes the input to the next layer. During training, the model adjusts its parameters using examples and a learning procedure.

\subsection{Training, validation and testing}
A dataset is often divided into separate parts for training, validation and testing. Training examples are used to fit model parameters. Validation examples help compare model settings during development. Test examples are held aside for a final evaluation after important choices have been made. The exact split depends on the amount and structure of the available data, and time-based data may require a time-aware split.

If examples from the same person or event appear in both training and test sets, the test result may be overly optimistic. This is a form of data leakage. Data preparation steps such as scaling should also be fitted using training data only and then applied consistently to validation and test data. A fair evaluation depends on keeping information from the test set out of the training process.

\subsection{Classification and regression}
Classification predicts a category, such as whether an image contains a cat or a dog. Regression predicts a numerical value, such as an estimated temperature. Accuracy can be useful for some classification tasks, but it may be misleading when one category is much more common than another. Precision and recall can provide additional information when false positives and false negatives have different consequences.

For regression, measures such as mean absolute error describe the typical size of prediction errors in the units of the target. The chosen measure should be explained in plain language. A model should also be compared with a simple baseline, such as always predicting the average, to check whether the more complex method adds value.

\subsection{Limitations of neural networks}
Neural networks may require substantial data and computing resources, and their behaviour can be difficult to explain. They can reproduce patterns and biases in training data. A high score on one dataset does not guarantee the same performance in a different school, region, language or time period. Monitoring, human review and clear limits on use are important where mistakes could affect people.

Data sources and external materials should be acknowledged.

\subsection{Choosing evaluation measures}
The measure depends on the task. A classification project may report accuracy and, where appropriate, precision, recall and a confusion matrix. A single score rarely tells the whole story.

A useful review considers whether the project solves the stated problem, whether the data and method are appropriate, whether the result can be reproduced, and whether limitations are acknowledged. \subsection{Planning the work and presenting results}
Before writing code, prepare a short plan with the project objective, required inputs, expected outputs and a list of tasks. Divide the work into manageable steps, such as preparing a data file, checking its quality, performing calculations, creating a chart and writing a conclusion. A small prototype should be tested early so that major problems are discovered before the final report is prepared.

The final presentation should explain the original question, the approach used and the evidence that supports the conclusion. Screenshots or diagrams can help readers follow the process, but they should be relevant and clearly labelled. If the result is uncertain or the dataset is small, state that limitation rather than making a broader claim than the evidence supports. Keep a copy of the code and note the software libraries required to run it.

\subsection{Defining a measurable project objective}
A good objective describes the problem, the intended user and the result that would count as useful. “Use AI to improve education” is too broad to guide a small project. “Create a chart that compares fictional marks across three subjects and explain the highest and lowest values” is specific and can be completed with a small dataset. If the project claims to predict an outcome, the report must explain how the prediction is trained and evaluated.

Before selecting a tool, ask whether AI is necessary. A clear set of rules or a simple chart may solve the problem more transparently than a machine-learning model. The best project is not necessarily the one with the most complex technology; it is the one that addresses the stated need safely and convincingly.

\subsection{Data permissions and documentation}
Use data that is permitted for the project. For classroom practice, fictional or appropriately anonymised examples are often sufficient. Do not upload personal records to online services unless there is a valid reason and appropriate permission. Keep track of the data source, collection date, fields, units, cleaning decisions and known limitations. If external code or images are used, acknowledge the source and respect its licence.

\subsection{A practical project schedule}
Divide a project into small tasks: define the question, prepare data, implement the method, test the result, create a visual explanation and write the report. Set a completion check for each task. Keep the scope realistic so that enough time remains for testing and documenting the work. If a step takes longer than expected, simplify optional features rather than skipping evaluation.

\subsection{Interpreting results honestly}
A result should be described in proportion to the evidence. A small sample may illustrate a method but cannot represent every learner or community. A correlation between two measurements does not prove that one causes the other. If the output changes substantially when one data point is removed, mention that sensitivity. Include failures and limitations as part of the report, not as details to hide.

\subsection{Project report structure}
A useful report can contain a title, problem statement, objective, data description, method, tools, implementation steps, results, evaluation, limitations, responsible-use considerations and conclusion. Each section should help the reader understand a different part of the work. Diagrams should be labelled, code should be formatted clearly, and every figure should be discussed in the text. A conclusion should answer the original question and avoid claims that were not tested.

\chapter{Computer System Architecture}
A computer is an electronic system that accepts data, processes it according to instructions, stores information and produces results. The same basic idea appears in desktop computers, laptops, smartphones, servers and embedded devices. Understanding the system underneath software helps a developer make sensible decisions about performance, storage, compatibility and troubleshooting.

The common stages are input, processing, output, storage and communication. A keyboard, camera or sensor supplies input. The CPU executes instructions and processes data. \section{CPU and its components}
The central processing unit (CPU) executes program instructions. The control unit coordinates operations, the arithmetic logic unit (ALU) performs arithmetic and logical comparisons, and registers hold small amounts of data immediately needed by the processor. Modern CPUs may contain multiple cores, allowing them to work on more than one stream of instructions.

\section{Memory and storage}

Cache is small, fast memory used to reduce the time needed to access frequently used data. Secondary storage, such as solid-state drives, hard disk drives, USB flash drives and memory cards, retains files and programs for longer periods.

\chapter{Data Representation in Computers}
Computers represent data using binary digits, 0 and 1. Electronic circuits can use two distinguishable states to encode these digits. Text, numbers, pictures, sound and video are all represented through patterns of bits, although the encoding rules differ.

\section{Bits, bytes and number systems}
A bit is a binary digit. A group of eight bits is called a byte. Larger quantities are commonly expressed using kilobytes, megabytes, gigabytes and terabytes; exact conventions may vary between decimal storage units and binary units such as KiB and MiB. Binary uses base 2, decimal uses base 10, octal uses base 8 and hexadecimal uses base 16.

\section{Converting number systems}
To convert a positive decimal integer to binary, repeatedly divide by two and record the remainders. Read the remainders from bottom to top. For example, decimal 13 becomes binary 1101 because \(13=8+4+1\). To convert binary 1011 to decimal, calculate \(1(2^3)+0(2^2)+1(2^1)+1(2^0)=11\).

Hexadecimal uses the symbols 0–9 and A–F, where A represents ten and F represents fifteen. One hexadecimal digit corresponds to four binary bits, making hexadecimal a compact way to read long binary values.

\section{Text, images and sound}
Character encodings assign numeric codes to characters. ASCII represents a basic set of characters; Unicode supports characters from many writing systems. UTF-8 is a widely used Unicode encoding for text on the web. Digital images use pixels and colour values; audio can be represented by samples taken at intervals. Image resolution, colour depth, sample rate and compression affect file size and quality.

\section{Data quality and safe handling}
Encoding does not guarantee that data is accurate. Developers must also validate inputs, use suitable data types, handle missing values and protect personal information. Files should have meaningful names and be backed up according to their importance.

\chapter{Basic Mathematics and Statistics for Computing}
Mathematics helps programmers describe relationships, compare values and reason about the behaviour of algorithms. Discrete mathematics focuses on distinct objects and structures, such as sets, logical statements, relations, functions, graphs and counting problems.

\section{Sets and operations}
A set is a collection of distinct elements. If \(A=\{1,2,3\}\) and \(B=\{3,4,5\}\), the union contains elements in either set, \(A\cup B=\{1,2,3,4,5\}\), while the intersection contains elements shared by both, \(A\cap B=\{3\}\). The difference \(A-B\) contains elements in A that are not in B. These ideas help model categories, permissions and relationships between data groups.

\section{Logic and truth values}
A proposition is a statement that can be true or false. Logical operators include AND, OR and NOT. In programming, conditions combine comparisons to decide which instructions should run. A truth table lists the possible inputs and resulting truth values and is useful when a condition becomes complicated.

\section{Relations, functions and graphs}
A relation describes a connection between elements. A function maps each valid input to exactly one output. Graphs consist of vertices and edges and can represent routes, social connections, network links or dependencies between tasks. Directed edges indicate direction; undirected edges represent a two-way relationship unless otherwise specified.

\section{Basic statistics}
Mean is the arithmetic average, median is the middle value after sorting, and mode is the most frequent value. Range is the difference between the maximum and minimum. Statistics help summarise test results, response times and software usage, but conclusions should consider sample size, data quality and unusual values.

\chapter{Problem-Solving Methods}
Programming begins with understanding a problem, not with typing code. A reliable solution identifies the expected result, the available input, the rules that transform input into output and the special cases that may cause failure.

\photo{../Junior software developer-11th/images/programming-code.png}{Writing and reviewing program code}{Figure 4.1. A programming editor helps developers write and inspect instructions; screenshot: Zhanjack822, Wikimedia Commons, CC0 1.0.}
\section{Define and analyse the problem}
Read the requirement carefully. Separate known facts from assumptions, identify constraints and ask questions where the requirement is unclear. Determine valid input ranges, expected output format and what should happen when data is missing or invalid. A small example often exposes misunderstandings early.

\section{Algorithms and pseudocode}
An algorithm is a finite, ordered set of steps for solving a problem. Good algorithms are clear, terminate, accept appropriate input and produce the required output. Pseudocode describes logic using plain structured language without committing to a particular programming language.

\begin{lstlisting}[style=webcode,language=Pseudo]

  INPUT first_number, second_number

  OUTPUT total
STOP
\end{lstlisting}

\section{Flowcharts}
Flowcharts use standard symbols to show the flow of a process. An oval commonly represents start or end, a parallelogram represents input or output, a rectangle represents a process, and a diamond represents a decision. Arrows show the direction of control. A flowchart should be readable and avoid crossing lines where possible.

\section{Testing and debugging}
A test checks whether a program behaves as expected for selected input. Test normal values, boundary values, invalid input and empty input where relevant. A syntax error breaks the language rules; a runtime error occurs while the program runs; a logic error produces an incorrect result without necessarily crashing. Debugging means locating and correcting the cause, then rerunning tests.

\section{Efficiency and documentation}
Efficiency can involve execution time and memory use. For small problems, clarity is often the most important goal; for large inputs, algorithm choice can make a substantial difference. Comments should explain intent or non-obvious decisions, while documentation describes how to install, run and use the software.

\chapter{Programming Language Concepts}
A programming language provides rules for expressing instructions that a computer can execute directly or through translation. Languages differ in syntax, type systems, abstraction, libraries, runtime environments and the kinds of problems for which they are commonly used.

\section{Machine, assembly and high-level languages}
Machine language consists of instructions encoded for a processor. Assembly language uses symbolic names for low-level instructions and is translated by an assembler. High-level languages such as Python, Java and C++ provide abstractions that make many programs easier to read and maintain.

\section{Compiler, interpreter and runtime}
A compiler translates source code into another form before execution; an interpreter executes instructions through a runtime process. Real language implementations may combine compilation, interpretation and virtual machines. A runtime provides services needed while a program executes, such as memory management or standard libraries.

\section{Syntax, semantics and paradigms}
Syntax describes the structure of valid expressions and statements. Semantics concerns their meaning. Procedural programming organises work into procedures or functions; object-oriented programming models data and behaviour through objects and classes; functional programming emphasises functions and expressions. Many languages support more than one paradigm.

\section{Development tools}
A code editor helps create and edit source files. An integrated development environment (IDE) may combine an editor, debugger, build tools, project navigation and testing support. Version control records changes over time and helps teams collaborate. Good naming, small functions, consistent formatting and clear commit messages improve maintainability.

\chapter{Operating System Fundamentals}
An operating system (OS) manages the hardware resources of a computing device and provides services to applications. It offers a consistent way to work with files, memory, devices, processes and users. Examples include Windows, Linux, macOS, Android and iOS.

\photo{../Junior software developer-11th/images/ubuntu-desktop.png}{Linux desktop environment}{Figure 6.1. The operating system provides the desktop, application launcher and workspace; screenshot: Canonical Limited, Wikimedia Commons, GPL.}
\section{Core responsibilities}
The OS schedules CPU time, manages memory, organises files, controls device access, provides a user interface and enforces security boundaries. It also detects certain errors and supports logging, networking and system updates. The kernel is the central component that manages privileged operations; shells and graphical interfaces allow users to interact with system services.

\section{Processes and memory}
A program is stored instructions; a process is a running instance of a program. The OS allocates CPU time and memory, tracks process states and coordinates input/output. Multitasking allows several tasks to make progress over time. Virtual memory helps manage address spaces and may use storage to extend the available memory model, though it is slower than RAM.

\section{Files, folders and permissions}
Files store content and folders organise files into a hierarchy. File names, extensions and metadata help users identify content. Permissions determine who may read, modify or execute files. Keep project files organised, use clear names, back up important data and avoid granting broader permissions than needed.

\section{User interfaces and maintenance}
A command-line interface accepts typed commands; a graphical user interface uses visual elements such as windows, menus and icons. Updates repair defects and address security issues. Install software from trusted sources, use standard user accounts for everyday work and keep recovery information available.

\chapter{Computer Networks}
A computer network connects devices so they can exchange information and share services. Networks support web browsing, messaging, file transfer, printing, online learning and distributed applications. A network may be small and local or connect devices across continents.

\photo{../Junior software developer-11th/images/lan-topology.png}{Local-area network topology}{Figure 7.1. A local-area network connects end devices through outlets, switches and a router; diagram: Mattias.Campe, Wikimedia Commons, CC BY-SA 3.0.}
\section{Network types and topologies}
A personal area network (PAN) connects nearby personal devices. A local area network (LAN) covers a limited site such as a home, laboratory or office. A wide area network (WAN) connects larger geographic areas. Common topologies include star, bus, ring and mesh; each has different cost, resilience and troubleshooting characteristics.

\section{Network devices}
A network interface connects a device to a network. Switches forward frames within a local network, while routers forward packets between networks. Wireless access points connect Wi-Fi devices. Modems or other access equipment connect a local network to an internet service. The exact device combination depends on the provider and network design.

\section{Addresses and name resolution}
A MAC address identifies a network interface at the link layer. An IP address supports logical addressing and routing. DNS translates domain names such as example.com into records used to locate services. DHCP can automatically assign network configuration such as IP addresses, gateway and DNS servers.

\section{Client-server and peer-to-peer}
In a client-server model, clients request services from servers. A web browser requesting a page is a common example. In peer-to-peer systems, devices can share responsibilities more directly. Both models require appropriate authentication, access control and safe handling of data.

\chapter{Transmission Media and Network Protocols}
Data travels through wired or wireless media. The medium affects speed, range, interference, installation cost and security. Network protocols define how devices format, address, transmit and interpret messages so that different systems can communicate.

\section{Guided and unguided media}
Twisted-pair copper cable is common in Ethernet LANs. Coaxial cable is used in some broadband and video systems. Optical fibre carries light and supports high bandwidth over long distances with low electromagnetic interference. Wireless communication uses radio waves, including Wi-Fi and cellular networks, and may be affected by walls, distance and interference.

\section{Protocol layers}
Layered networking divides a complex communication task into manageable responsibilities. Ethernet and Wi-Fi operate at the link level; IP provides addressing and routing; TCP offers reliable ordered delivery; UDP offers a simpler datagram service; HTTP and HTTPS support web communication. TLS helps protect communication against eavesdropping and tampering when configured correctly.

\section{Packets and ports}
Applications send data through protocols that may divide it into packets or segments. Port numbers help the operating system deliver traffic to the appropriate service. Firewalls can allow or block traffic according to rules. Open only the ports required for a service and keep network software updated.

\section{Troubleshooting connectivity}
Check power and physical connections first. Confirm Wi-Fi or Ethernet status, then inspect IP configuration and DNS resolution. Try to isolate whether the problem affects one device, one service or the whole network. Record error messages and change one variable at a time so the cause can be identified.

\chapter{Network Security}
Network security protects systems, communications and information from unauthorised access, misuse and disruption. Security depends on technology and human behaviour: even well-designed systems can be exposed by weak passwords, unpatched software, unsafe configuration or deceptive messages.

\photo{../Junior software developer-11th/images/router-vlan.png}{Router and virtual LANs}{Figure 9.1. A router can route traffic between separate virtual LANs; diagram: Anatoly099, Wikimedia Commons, CC BY-SA 4.0.}
\section{Threats and vulnerabilities}
Malware includes viruses, worms, trojans, ransomware and spyware. Phishing attempts to trick people into revealing information or running unsafe files. Password attacks, unpatched services, misconfiguration and denial-of-service attacks can affect confidentiality, integrity or availability. A vulnerability is a weakness that a threat may exploit.

\section{Security controls}
Use strong unique passwords and multifactor authentication where available. Apply updates, use endpoint protection, enable firewalls and restrict privileges. Back up important information and test restoration. Encrypt sensitive data in transit and at rest where appropriate. Security controls should be selected based on the risks and the value of the information being protected.

\section{Safe network behaviour}
Verify unexpected links and attachments through a trusted channel. Avoid entering credentials on unfamiliar pages. Use secure Wi-Fi configurations and be cautious on public networks. Do not share passwords or one-time codes. Report suspicious activity promptly and preserve relevant details according to organisational procedure.

\section{Incident response}
A basic response includes identifying the event, limiting further harm, informing the appropriate people, preserving evidence, recovering safely and reviewing what can be improved. Do not attempt to hide an incident or destroy records. Follow organisational policy and applicable law.

\chapter{Python Basics}
Python is a high-level, general-purpose programming language used for automation, data analysis, web development, scientific computing and many other tasks. Its readable syntax makes it suitable for learning programming concepts while still supporting large applications.

\photo{../Junior software developer-11th/images/python-simulation.jpg}{Python programming}{Figure 10.1. A Python program can combine source code and a visual output window; screenshot: MikeRun, Wikimedia Commons, CC BY-SA 4.0.}

Use the official Python distribution or an approved environment. The interpreter executes Python statements. IDLE is a simple environment that includes an editor and interactive shell; other editors and IDEs are also available. Check the installation by running a short command and confirming the version reported by the system.

\begin{lstlisting}[style=webcode,language=Python]
print("Hello, learner!")

The first line displays a message. The second reads text from the user and stores it in a variable. The final line combines output with the entered value.

A variable is a name that refers to a value. Identifiers should be meaningful and follow Python's naming rules. Common types include int for integers, float for floating-point numbers, str for text, bool for true/false values, and collections such as list, tuple, set and dict. Python is case-sensitive, so \texttt{score} and \texttt{Score} are different names.

\section{Operators and expressions}
Arithmetic operators include +, -, *, /, //, \% and **. Comparison operators include ==, !=, <, >, <= and >=. Logical operators and, or and not combine conditions. Parentheses make complicated expressions easier to read. Use explicit conversion such as \texttt{int(input(...))} when numeric input is required, and handle invalid input where necessary.

\section{Comments, indentation and errors}
Comments begin with the hash symbol. Indentation defines blocks in Python and must be consistent. Syntax errors prevent code from being parsed; exceptions occur during execution; logic errors produce the wrong answer. Read tracebacks from the final error message and inspect the relevant line before changing code.

\chapter{Control Structures}
Control structures determine the order in which instructions run. Sequence executes statements in order, selection chooses between alternatives, and iteration repeats a block. These structures allow a program to respond to input and process collections of data.

\section{Selection with if}
An \texttt{if} statement runs a block when a condition is true. \texttt{elif} checks another condition, and \texttt{else} provides a fallback. Conditions may use comparison and logical operators.

\begin{lstlisting}[style=webcode,language=Python]
marks = int(input("Enter marks: "))
if marks >= 80:
    print("Grade A")
elif marks >= 60:
    print("Grade B")
elif marks >= 40:
    print("Grade C")
else:
    print("Needs improvement")
\end{lstlisting}
The order matters: the most restrictive threshold is tested first. Validate input ranges if marks must lie between 0 and 100.

\section{Iteration with for and while}
A \texttt{for} loop is useful for iterating over a sequence or range. A \texttt{while} loop repeats while a condition remains true. Each loop should make progress toward termination unless it is intentionally designed to run continuously.

\begin{lstlisting}[style=webcode,language=Python]
for number in range(1, 6):
    print(number)

count = 3
while count > 0:
    print(count)
    count -= 1
\end{lstlisting}

\section{Loop control and tracing}
\texttt{break} exits a loop and \texttt{continue} skips to the next iteration. A trace table records variable values at each step and is useful for checking a loop's logic. Avoid changing many variables in a single step when debugging a beginner program.

\chapter{Functions}
A function is a named block of code that performs a defined task. Functions help divide a problem into smaller parts, avoid repeated code and make programs easier to test. A function can receive inputs called parameters and return a result.

\section{Defining and calling functions}
Use the \texttt{def} keyword to define a function. The indented body contains the instructions. Calling a function runs that body; a return statement sends a value back to the caller.

\begin{lstlisting}[style=webcode,language=Python]
def rectangle_area(length, width):
    return length * width

area = rectangle_area(8, 3)
print("Area:", area)
\end{lstlisting}

\section{Parameters, arguments and scope}
Parameters appear in the function definition; arguments are values supplied when it is called. Local variables are created within a function and normally cannot be accessed directly outside it. Default parameters can make an argument optional. Choose names that communicate the purpose of each value.

\section{Built-in and user-defined functions}
Python provides built-in functions such as \texttt{print}, \texttt{input}, \texttt{len}, \texttt{type}, \texttt{sum}, \texttt{min} and \texttt{max}. User-defined functions capture a task specific to a program. A useful function has a clear responsibility, predictable inputs and outputs, and a name that explains its role.

\section{Testing functions}
Test normal cases, boundary values and invalid inputs. A function that calculates a percentage should define what happens when the total is zero. Small tests make errors easier to isolate and allow later changes without manually checking every part of the application.

\chapter{Strings}
A string is an immutable sequence of characters. Strings represent names, messages, addresses, codes and other text. Because strings are immutable, an operation that appears to change a string normally returns a new string rather than altering the original object.

\section{Creating and accessing strings}
Strings can be written with single or double quotes. Triple quotes can represent multiline text. Indexing accesses a character; positive indexes start at zero, while negative indexes count from the end. Slicing selects a range and uses an exclusive stop index.

\begin{lstlisting}[style=webcode,language=Python]
word = "Python"
print(word[0])      # P
print(word[-1])     # n
print(word[1:4])    # yth
print(len(word))    # 6
\end{lstlisting}

\section{String methods}
Useful methods include \texttt{lower}, \texttt{upper}, \texttt{strip}, \texttt{replace}, \texttt{split}, \texttt{join}, \texttt{startswith} and \texttt{endswith}. The \texttt{in} operator checks whether a substring is present. Methods should be selected based on the intended transformation and the format of the input.

\section{Formatting and validation}
F-strings make it convenient to insert values into text, for example \texttt{f"Hello, \{name\}"}. User input should be validated for expected length, allowed characters and required format. Validation is not the same as security by itself; applications should also apply context-appropriate encoding and access controls.

\chapter{Lists}
A list is an ordered, mutable collection that can hold multiple values. Lists are useful when a program needs to store, examine, sort or update a group of items. List elements can have different types, although collections with a consistent type are often easier to work with.

\section{Creating and accessing lists}
A list uses square brackets. Indexing retrieves an element and slicing retrieves a sublist. Lists support updates, append, insert, remove, pop, sort and reverse. These operations change the list in different ways, so consult the method's purpose before using it.

\begin{lstlisting}[style=webcode,language=Python]
scores = [72, 85, 64, 91]
scores.append(78)
scores[0] = 75
print(scores)
print("Count:", len(scores))
print("Highest:", max(scores))
\end{lstlisting}

\section{Traversing and processing}
A for loop can visit each element. A running total can calculate a sum, and a condition can count values that meet a requirement. Python also provides built-in functions and comprehensions for common transformations. Begin with a clear loop when learning, then use concise expressions when their meaning remains easy to understand.

\section{Nested lists and common mistakes}
A list can contain other lists, which can represent rows and columns. Indexing outside the valid range raises an error. Removing an item while iterating over the same list can lead to skipped values; when filtering, creating a new list is often safer.

\chapter{Tuples and Dictionaries}
Tuples and dictionaries organise related data in different ways. A tuple is ordered and immutable. A dictionary maps unique keys to values and is useful when values need to be retrieved by a meaningful label.

\section{Tuples}
Tuples are written using commas, often inside parentheses. They are useful for fixed groups of values, such as coordinates or a returned pair of results. A one-element tuple requires a trailing comma. Since tuples are immutable, their element assignments cannot be changed after creation.

\section{Dictionaries}
A dictionary uses key-value pairs. Keys must be hashable and unique within the dictionary. Values can be updated, added or removed. Methods such as \texttt{keys}, \texttt{values}, \texttt{items}, \texttt{get}, \texttt{update} and \texttt{pop} support common operations.

\begin{lstlisting}[style=webcode,language=Python]
learner = {
    "name": "Ananya",
    "grade": 11,
    "active": True
}
print(learner["name"])
learner["grade"] = 12
print(learner.get("course", "Not assigned"))
\end{lstlisting}

\section{Choosing a collection}
Use a list when order and changeable elements are important. Use a tuple for a fixed sequence. Use a dictionary when a key should identify a value. Choose the structure that makes the data and intended operations easiest to understand.

\chapter{Introduction to Data Structures}
A data structure is a way of organising data so that operations can be performed effectively. Different structures support different patterns of access, insertion, deletion and searching. Choosing a suitable structure can improve clarity and performance.

\section{Abstract data types and operations}
An abstract data type describes the behaviour expected from a collection without requiring one specific implementation. Common operations include insert, delete, search, traverse and update. A stack, for example, supports adding and removing items at one end; a queue processes items in arrival order.

\section{Linear and non-linear structures}
Linear structures arrange elements in a sequence, as in arrays, linked lists, stacks and queues. Non-linear structures express branching or network relationships, as in trees and graphs. A structure's usefulness depends on the problem rather than on whether it is more advanced.

\chapter{Linear Data Structures}
Linear data structures arrange elements in a sequence. Arrays, linked lists, stacks and queues are common examples. Each offers a different balance between access speed, insertion, deletion and memory organisation.

\section{Arrays}
An array stores elements in indexed positions. Index-based access is efficient when the position is known. Inserting or deleting elements in the middle may require moving other values. Python lists behave like dynamic arrays for many common uses.

\section{Linked lists}
A linked list contains nodes. Each node stores data and one or more links to other nodes. A singly linked list points to the next node; a doubly linked list points both forward and backward. Linked lists can insert or remove nodes efficiently when the relevant position is known, but finding a distant element usually requires traversal from the start.

\section{Stacks}
A stack follows last-in, first-out (LIFO). The main operations are push, pop and peek. A stack models undo operations, function calls and expression evaluation. Removing from an empty stack should be handled as an error or an explicitly defined empty result.

\section{Queues}
A queue follows first-in, first-out (FIFO). Enqueue adds an item and dequeue removes the oldest item. Queues model print jobs, service requests and tasks waiting for processing. Circular queues can reuse array space, while priority queues process items according to priority rather than arrival order.

\chapter{Non-Linear Data Structures}
Non-linear data structures represent branching or many-to-many relationships. Trees are hierarchical; graphs model general connections. These structures appear in file systems, routing, dependency analysis, maps and social networks.

\section{Trees and terminology}
A tree consists of nodes connected by edges and has a root node. A parent can have child nodes; a node without children is a leaf. A subtree is a node together with its descendants. A binary tree allows each node to have at most two children. A binary search tree arranges values so that values in the left subtree are smaller and values in the right subtree are larger, according to its ordering rule.

\section{Tree traversal}
Pre-order visits root, left subtree, right subtree. In-order visits left subtree, root, right subtree. Post-order visits left subtree, right subtree, root. For a binary search tree, in-order traversal visits keys in sorted order if the tree follows the required ordering rules.

\section{Graphs}
A graph consists of vertices and edges. It can be directed or undirected, weighted or unweighted. A path is a sequence of connected vertices; a cycle returns to a previously visited vertex. Graphs can be represented by an adjacency list or adjacency matrix. An adjacency list stores neighbours for each vertex, while a matrix records whether pairs of vertices are connected.

\section{Applications}
Trees can represent folders, organisational structures and syntax. Graphs can represent road networks, computer networks and links between web pages. The representation should match the expected operations and the size and density of the structure.

\chapter{Relational Database Foundations}
\section{Data and information}
Data are recorded facts such as student numbers, prices, dates or quantities. Information is data arranged to answer a question. A database is an organised collection of related data that can be searched and updated consistently. A database management system (DBMS) defines, stores, retrieves and protects data. A relational DBMS represents data through tables of rows and columns.
\section{File systems and databases}
Independent files may duplicate values and become inconsistent when only some copies are updated. A DBMS supports controlled access, validation, shared data, backup and query-based retrieval. These benefits depend on sound design and configuration.

\chapter{SQL Functions and Relational Design}
Single-row functions transform values per row. String functions change case or measure text; numeric functions round values; date functions work with calendar values. Aggregate functions such as COUNT, SUM, AVG, MIN and MAX summarise groups. COUNT(column) generally excludes null values, while COUNT(*) counts rows.
\begin{lstlisting}[language=SQL]

       CHAR_LENGTH(FullName) AS NameLength

Normalisation reduces duplication and update anomalies. First normal form expects atomic values and no repeating groups. Second normal form removes partial dependencies on part of a composite key. Third normal form removes inappropriate transitive dependencies among non-key attributes.

\chapter{Python Data Structures: Stack and Queue}
A stack follows last-in, first-out (LIFO); the last item added is removed first. A queue follows first-in, first-out (FIFO); the earliest item is removed first. Stacks suit undo histories and function calls; queues suit print jobs and service requests.
\photo{../Junior software developer-12th/images/stack-queue.png}{Stack and queue comparison}{The structures differ in the order items leave the collection. Source and licence are listed in IMAGE-CREDITS.txt.}
\begin{lstlisting}[language=Python]
from collections import deque
stack = []
stack.append("first")
stack.append("second")
print(stack.pop())       # second
queue = deque(["first", "second"])
queue.append("third")
print(queue.popleft())   # first
\end{lstlisting}
Use deque for efficient queue operations. Test empty structures and decide how to handle attempts to remove an item when none exists.

\chapter{Exception Handling in Python}
A syntax error prevents parsing; a runtime exception occurs during execution; a logic error produces an incorrect result even though the program runs. Use try for risky operations, except for expected exception types, else for success-only actions and finally for cleanup.
\begin{lstlisting}[language=Python]
raw = input("Enter a whole number: ")
try:
    value = int(raw)
except ValueError:
    print("Please enter a valid whole number.")
else:
    print("Double:", value * 2)
finally:
    print("Input attempt finished.")
\end{lstlisting}
Catch the narrowest useful exception. Avoid broad handlers that hide defects. Raise an exception when an input violates a function's documented contract.

\chapter{File Handling in Python}
Text files store characters; binary files store bytes. Modes include r for reading, w for replacing content, a for appending and x for exclusive creation. The with statement closes files reliably after a block.
\begin{lstlisting}[language=Python]
with open("notes.txt", "w", encoding="utf-8") as file:
    file.write("Python file handling\n")
with open("notes.txt", "r", encoding="utf-8") as file:
    print(file.read())
\end{lstlisting}
CSV stores rows and columns; Python's csv module handles quoted values. JSON represents objects, arrays and primitive values and is commonly used by APIs. Validate user-provided files, avoid overwriting valuable data without backups and never commit secrets to source control.
\begin{lstlisting}[language=Python]
import csv
with open("marks.csv", newline="", encoding="utf-8") as file:
    for row in csv.DictReader(file):
        print(row.get("StudentName"), row.get("Marks"))
\end{lstlisting}
